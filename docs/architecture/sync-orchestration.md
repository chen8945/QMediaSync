# STRM 同步调度与任务记录

> 职责：定义保存型同步目录的触发、Cron、按来源分队列、`sync` 任务记录、取消和下游协作边界。
>
> 权威范围：本文档维护完整 STRM 同步的运行链路；STRM 文件生成、目录监控上传和上传后处理见 [上传和 STRM 后处理](upload-and-strm-processing.md)，实时消息协议见 [实时事件](realtime-events.md)，任务机器值见 [任务来源](../reference/task-sources.md)。
>
> 修改时机：修改同步入口、Cron 注册、队列路由、去重、取消、`sync` 状态或同步完成后的下游触发时必须更新本文档。
>
> 相关代码：`backend/internal/controllers/sync.go`、`backend/internal/syncconfig/`、`backend/internal/synccron/`、`backend/internal/syncstrm/`、`backend/internal/models/sync.go`、`backend/internal/models/syncpath.go`。

## 范围和对象

`sync_paths` 是可保存、可调度的同步目录：它绑定来源类型、账号、远端路径、STRM 本地目录和可继承的 STRM 配置。创建和更新通过 `POST /api/sync/paths`、`PUT /api/sync/paths/:id` 的聚合保存完成；保存成功后重载同步目录自定义 Cron，并在需要时重载目录监控服务。精确请求、幂等和错误契约见 [同步目录聚合 API](../reference/sync-path-api.md)。

前端通过同步目录领域 API 校验 HTTP 状态和业务响应后，才执行保存、启停或关联的成功反馈。停止接口成功表示取消请求已提交，任务终态仍由后续快照确认；操作成功后的加载失败应说明刷新问题。公共错误分类与提示边界见 [前端开发约定](../engineering/frontend-development.md#api-响应与请求错误)。

同步记录列表、删除和清理也使用领域 API 进行成功判定。失败不触发成功后的刷新或清除选择；现有分页、筛选请求合并与实时事件过期保护继续生效。手动 STRM 生成失败时，文件管理器保留用户选择的目标目录以便修正或重试。批量 STRM 生成复用该入口对选中项逐项提交，每项独立解析路径、入队并创建临时记录，队列按文件 ID 与任务类型拒绝重复任务；提交期间切换目录或账号即中止剩余提交，全部失败保留弹窗和已选目标，部分成功汇总数量后关闭弹窗。

`POST /api/sync/manual` 是临时同步入口。它使用请求中的账号、文件或目录和目标路径，不对应保存的 `sync_paths`，运行时使用临时 ID 创建记录；不会提交 Emby 刷新，也不会触发关联刮削。临时记录可以按临时记录规则删除，但不应被当作可再次调度的同步目录。

网盘文件管理通过该入口生成 STRM，使用全局 STRM 设置。单文件和目录生成都检查原有完整名称排除及正则排除，父目录命中也会跳过文件；保存型同步目录使用同一排除判断并按自定义列表继承规则取值。名称与正则语义由 [STRM 名称排除](../operations/configuration.md#strm-名称排除) 维护。

完整同步的远端处理与本地核对使用同一本轮排除规则，优先于元数据上传、删除和附属目录补建。目录命中时跳过整个子树，文件命中时只跳过该文件；不生成 STRM、不新增下载或上传任务，不为这些项目补查上传目录、建目录、覆盖或清理本地文件。已有本地 STRM、元数据、空目录及对应旧账本保留，源视频名称排除同样保护其已生成的 STRM。按本地 STRM 文件名排除时，对应旧账本也须保留，包括修改输出目录后仍指向旧位置的记录。排除是正常跳过，不计作失败或扫描不完整；未排除兄弟继续按原规则处理。远端扫描可能先取得列表或路径才能识别排除项，不能据此承诺零网盘请求；本轮规则不撤销或重新筛选已经排队的传输任务。

完整同步与上传后单文件 STRM 处理必须分开：前者创建 `sync` 记录、进入同步队列并处理目录差异；后者由 `strm_generation_tasks` worker 执行，不创建完整同步记录。

百度同步在运行时将远端根路径统一为以 `/` 开头的路径，空根路径表示 `/`，保留目录名中的空格；保存的同步目录配置格式不变。增量范围检查、失败子树保护和账本查询使用同一运行时路径，避免把合法的绝对路径误判为根目录之外。

保存型同步目录的单文件 STRM 生成在范围校验时，同样将已保存的空 `remote_path` 视为网盘根目录 `/`，不改写配置存储值。

百度目录列表按远端原始页长推进分页：满 50 项继续请求，短页结束；恰好 50、100 项时会再请求空页确认结束，名称排除后的数量不参与分页判断。后续页请求失败或连续完整页的文件身份完全重复时返回错误，不将已经取得的部分列表作为完整目录交付。扫描层保护失败目录及后代，继续处理独立兄弟目录；这不代表任意服务端分页变化都已获得快照一致性保证。

115 递归文件扫描按过滤前的页长、唯一文件 ID、远端 Count 和首次文件身份检查完整性。异常空页、缺页、重复身份或无法定位的路径不能获得整根缺项清理资格；未知候选可能改变同名 STRM 归属时保留既有 STRM。完整页中可独立定位的文件仍可继续处理。这些检查不能检测所有等量替换或移动，远端列表不是事务快照。 115 列表业务失败不得解释为空目录；非播放请求保留类型化认证错误，已收到 HTTP 401 时授权失败优先于响应正文读取／解析失败，其他非认证错误不一律升级为账号失效。

115 增量同步可复用同账号、同来源、同同步目录的持久目录路径及父子关系；全量和临时同步重新确认位置。历史缓存完整且目录没有已知变化时，不再逐个补查旧目录；账本保留被本轮文件引用的历史祖先关系。日志分别统计父目录总数、可复用数和待查询数，候选数不等于实际 HTTP 数。本轮成功响应优先于历史信息，已知移动、改名或路径身份替换会更新或失效关联历史位置，缺少可靠路径的目录按需补全；历史信息与新响应不同不等同于本轮响应相互冲突。排除规则仍按本轮配置重新应用。外部客户端修改目录而 QMS 尚未取得新信息时，增量可能暂用旧路径，直到全量或主动刷新。若本地核对阶段才取得与已应用历史矛盾的新位置，标记整根扫描不完整以保护清理和账本；已生成的文件不在本轮回滚。

一份目录详情中的完整祖先链仍可供本轮后续待查目录使用；路径请求真正开始前再检查一次可复用信息，原有文件分页、直接父目录去重和并发数不变。预取目录先检查身份与路径，再参与复用。进程重启会清空内存工作集，但已入账的目录路径可从数据库重新加载，不因此补查全部远端目录。

115 递归文件列表不包含空目录，文件总数为零或目录缓存未命中都不能证明目录已删除。处理“远端缺失时上传”的本地元数据时，优先复用本轮确认的目录位置及完整直接子目录列表。完整列表须通过全部分页、数量、身份与路径唯一性及父目录校验，保存排除过滤前的目录信息。115 的 `stdir=1` 不保证只返回目录：合法普通文件参与原始页数量和身份校验，再从目录结果中滤除。成功空列表同样有效，但也须确认响应父目录的 ID 和当前位置与待核对的父目录一致；不能用已移动父目录的空列表证明旧路径缺失。某个父目录已完整列举且目标缺席时，无须再查目标路径或旧 ID。完整性只覆盖实际列举的这一层；确认某个祖先缺失后，才可将缺失结论用于其旧路径下的后代。旧账本只用于定位，不能充当本轮缺席证明。

没有充分的本轮信息时，先使用同账号、同来源、同同步目录的唯一旧目录 ID 查询当前位置。旧 ID 仍在原路径则确认存在；已移动、改名或删除时，仍须确认原路径是否被同名新 ID 占用。旧目录移出同步根本身不算查询失败，其位置仅用于核对，不扩大生成、上传或清理范围。没有可靠旧 ID 时查询当前路径，完整详情直接复用，明确且有效的路径不存在响应可确认缺失。按路径查询成功但 `data=[]` 只表示未取得详情，不能直接转换成删除错误；`{}`、`null`、缺少身份和矛盾响应也不能作为缺失证明。

原路径仍未确认时，按需完整列举其直接父目录；父目录位置未知则从最近已确认的祖先沿目标分支逐级检查，某一级缺失便停止，不扫描整棵树。同一目录和父目录列表只在本轮共享。补查成功后不保留最初空查询的失败状态；最终仍无法判断时，保留相关本地文件和旧账本，记录扫描不完整。认证失败、取消和必要数据库错误仍停止执行。旧目录不存在等普通错误不能遮蔽后续补查的认证失败；补查失去授权后停止本地核对，不继续清理后续目录。本轮存在与缺席信息冲突时继续保护，不能用后到的结果覆盖先前事实。

未命中排除规则的本地缺失元数据，确认普通父目录存在后才上传；确认原路径不存在时，按既有逐文件规则清理本地 STRM 和元数据，空目录按设置处理，不递归删除整个本地目录。115 同步允许补建白名单附属目录，但其普通影片、剧名或季目录必须仍在原位置；不能为了上传附件递归重建已缺失的普通祖先。驱动确认目标目录已经存在时直接复用目录 ID，不再进入创建流程。创建成功后更新本轮目录信息，废弃创建前的缺席结论。非上传模式及关闭元数据处理继续按原规则执行，不因此增加目录请求。其他来源的附属目录创建规则保持原行为；白名单由 `sync_config_validate.go` 的 `uploadDirNames` 维护。

本地核对先复用本轮已确认的目录存在或缺席结论；没有充分证据时仍先确认上传父目录，再处理其中的文件。文件继续逐项遵循排除、失败保护和元数据策略。空目录检查集中在文件遍历成功结束之后，对本轮访问的目录从子到父各检查一次，使只有多层子目录的空壳也能在本轮清理。每次收尾仍重新检查取消、清理设置和最新保护范围；取消或致命错误后不继续收尾，读取或删除目录失败计入相应目录的扫描失败。目录缓存清理沿用本轮已删文件的直接父目录范围，不因本地初始空目录或更高祖先被删除而丢弃本轮已确认的远端目录记录。

上传模式处理缺失元数据前仍查询同来源、同一本地完整路径的活跃上传任务，命中则保留本地文件；来源为 `strm_sync`，不额外按账号或同步目录缩小保护范围。本轮目录结论不能代替这项查询。查询只判断任务是否存在，不统计数量，也不使用整轮固定的任务快照；必要数据库查询失败会停止本地核对，保留尚未处理的文件。正常同步缓存缺项继续保留 WARN 日志，便于排查移动和删除。

所有路径请求结束后才统一补齐文件路径和应用目录排除，避免并发响应出现矛盾时已经丢掉文件。同一目录 ID 在本轮返回不同位置时，整根标为扫描不完整，本轮待补路径文件不生成，也不做缺项清理。新一轮重新确认目录位置并使用新规则，不沿用旧轮排除结果；服务端没有提供目录快照版本，仍不能保证发现所有请求之间发生的云端移动。

百度每天首次全量的依据是服务器当地自然日内已经成功完成的全量任务；当前运行记录、失败记录和成功增量都不能证明当天已完成全量。增量按服务端 `has_more` 和可推进的 cursor 翻页；新返回的路径和 fs_id 优先于旧账本，规则排除的新事实也不能被旧行重新加入。仅观察到目录移动、无法确认后代新路径时，保护旧新子树并显示扫描不完整，等待原定全量核对。增量不凭未出现项执行缺项清理，不自动增加扫描。

百度本轮成功文件以稳定 fs_id 确认移动时，先持久化新路径事实，再淘汰同范围内被其替代的精确旧账本行，避免下一次空增量回灌旧路径。新事实写入失败时保留旧行；旧本地 STRM 仍等待原定全量按清理资格处理。这是已知身份替代，不把增量缺项当作删除依据。

百度全量扫描中，已发现目录移动但新位置读取失败时，按同账号、同同步目录内的稳定 fs_id 关联旧目录，同时保护旧、新子树的全部本地文件和账本，包括旧账本指向的原本地位置。不能只保护报错的新路径，也不能只保留目录本身而清掉后代；无法可靠界定旧范围时暂停整个同步根的缺项清理。能确认独立完整的兄弟目录仍可继续处理。

## 触发与 Cron

| 触发入口 | 适用范围 | 结果 |
| --- | --- | --- |
| `POST /api/sync/start` | `enable_cron=true` 且没有自定义 Cron 的保存型同步目录 | 将每个目录加入对应来源队列 |
| `POST /api/sync/path/start` | 指定保存型同步目录 | 将该目录加入对应来源队列 |
| `POST /api/sync/path/full-start` | 指定保存型同步目录 | 先写入 `is_full_sync=true`，再加入对应来源队列 |
| 全局 STRM Cron | 同 `POST /api/sync/start` | 调用 `StartSyncCron()`，不直接执行同步 |
| 同步目录自定义 Cron | `enable_cron=true` 且 `sync_paths.cron` 非空的保存型目录 | 由 `SyncCron` 独立注册并入队 |
| `POST /api/sync/manual` | 临时文件或目录同步 | 以临时任务入队 |

全局和自定义 Cron 互斥：全局 Cron 会跳过配置了自定义表达式的目录；自定义 Cron 只加载已开启定时同步且表达式非空的目录。修改全局 Cron、同步目录自定义 Cron 或 `enable_cron` 后，必须重载相应 scheduler，不能依赖旧的已注册任务自然失效。

全局 Cron 每小时的维护入口同时清理请求统计和 115 多端播放残留，包括符合归属条件的回收站操作目录。多端播放维护逐账号执行，重叠触发会合并；它与播放请求共用同一编排器以避开活跃目录，不创建同步任务记录。每轮开始时读取多端播放开关，关闭时跳过整轮播放维护，包括待重试清理、根目录定位、目录枚举和回收站扫描；请求统计清理照常执行。重新开启后从下一次整点维护恢复。目录归属、保留时间和清理预算见 [115 多端播放链路](upload-and-strm-processing.md#115-多端播放链路)。

## 按来源队列

同步调度器为每个 `source_type` 延迟创建一个内存队列；同一来源队列串行执行，来源不同的队列可以并发执行。每条队列任务使用 `sync_path_id-task_type` 作为保存型任务 key，`task_type` 使用稳定机器值 `strm_sync`；同一个目录处于等待或运行时，重复入队会被拒绝。临时任务以 `source_path_id-task_type` 去重。

单队列通道和等待集合的容量均为 `50`。队列暂停时新任务仍留在等待集合，恢复后重新投递；停止服务会取消队列 context、关闭通道并清空内存等待状态。因此队列不是持久化消息系统，进程重启后不会恢复尚未执行的队列项。

`POST /api/sync/path/stop` 的语义取决于任务状态：等待项直接从等待集合移除；运行中的 STRM 同步调用 `SyncStrm.Stop()` 取消 context。接口以成功响应表示已发起取消，最终结果以 `sync` 记录状态、日志和 SSE 事件为准。

执行器在已启动的扫描工作返回后统一记录失败；预取 worker 不直接发布任务终态。取消会作为错误返回来源队列，失败收尾使用独立的有界 context 等待旧进度并保存失败状态；数据库写入失败时保留错误，不伪造已经持久化的成功或失败事件。进度与终态的发布顺序见 [实时事件](realtime-events.md#日志-tailer-与事件字段)。

```text
HTTP / Cron / Telegram
          │
          ▼
  按 source_type 的内存同步队列
          │  去重、容量检查、取消
          ▼
 SyncStrm 创建 sync 记录并执行
          │
          ├── 写入 STRM、下载和上传任务
          ├── 发布同步任务事件和日志
          └── 完成后按变化触发 Emby 刷新与关联刮削
```

## `sync` 记录与执行状态

保存型和临时完整同步开始时都创建 `sync` 记录。状态使用稳定整数：`0` 待处理、`1` 进行中、`2` 已完成、`3` 失败、`4` 部分完成、`5` 扫描不完整、`6` 已取消；子状态为无、处理网盘文件和处理本地文件列表。`scan_result` 保存实际成功、失败、跳过数量、失败文件／目录及原因、缺项清理结果。未知目录的文件数不计作失败文件数；历史记录没有明细时显示“未记录”。进度、结果通过数据库记录与同步任务 SSE 共同暴露，字段见 [数据库 schema](../reference/database-schema.md#syncs)，断线恢复见 [实时事件](realtime-events.md)。

文件错误只隔离失败文件及关联旧新目标；目录读取失败保护该子树与包含它的祖先删除。独立完整范围可以继续生成与清理。无法定位的 115 缺页保护整个根；本地 Walk、目录读取和必要 SQL 错误不能忽略。账号认证失效、必要数据库失败和取消停止继续调度，并等待已经启动的工作退出。本地同步保留旧账本供失败保护使用，不在扫描前清空。失败范围可通过现有手动文件／目录入口补做；临时补做不推进保存型根目录的成功水位。

远端目录探测不能把认证失败当作目录不存在并继续向上探测或创建；115、百度和 OpenList 的目录创建错误保留原错误链，使本地核对收到认证失败后停止处理剩余文件。

单文件生成也记录已知的成功、失败或跳过结果；规则排除及掩码路径的跳过不会因外层调用正常返回而改计成功。入口提前排除已知单文件时仍计 1 个跳过；目录入口整体排除时不推算子树文件数。跳过计数只描述本次扫描处理结果，不代表异步下载、上传或后处理任务已经完成。

执行器启动时会暂停全局下载和上传队列，完成或返回后再启动它们；同步过程中产生的元数据下载和上传工作由各自的持久化队列处理。不要把内存同步队列的等待状态与下载、上传队列的持久化状态混为同一种任务状态。

新增本地元数据回传时，先按本地实际同步根目录判断文件是否直接位于根下，再确定来源侧的完整目标父目录。local 的本地根为 STRM 目标目录，来源根为挂载目录；其他来源的本地根包含来源路径。已有目录通过缓存的路径访问方法读取完整来源路径，local 和 OpenList 不直接读取缓存的 `Path` 字段。local 新建附属目录的缓存与扫描结果保持相同路径语义，并在本轮立即可按本地路径查询；创建目录返回完整目标父路径。本地上传文件路径直接保存规范化后的扫描路径，与活跃上传去重查询一致。入队后目标由上传任务的 `remote_full_path` 固定保存，不再补根或重算，相关字段约定见[上传处理](upload-and-strm-processing.md#115-上传增强)。历史错误任务不自动改写，已传错位置或已删除的文件不自动恢复。

本地核对选择“网盘不存在的元数据：上传”时，已确认失效的视频版本不会使专属元数据重新上传：本轮本地存在对应 STRM、远端视频及元数据均缺失且允许清理时，同目录精确同名的 NFO、图片及带明确图片后缀（如 `-thumb`、`-poster`）的图片会清理本地残留。归属优先完整名称，再匹配图片后缀；仍有存活视频使用的文件保留原有同步行为。通用 NFO、共享图片和季海报不随单集或单版本清理，字幕等其他元数据仍按原配置处理。排除项、失败保护、范围校验和活跃上传保护继续生效；扫描不允许按缺项清理时不应用该规则。该规则在处理每个本地目录前额外读取一次目录名称，仅在本轮内存中保留失效 STRM 路径，避免关联依赖文件遍历顺序；判断复用远端内存缓存，不新增网盘请求或历史账本查询，删除前仍保留原有活跃上传查询。历史任务和已回传的远端残留不自动修复。

元数据下载和修改时间检查以远端官方修改时间为准。115 列表使用 `upt`、详情使用 `utime`，仅在该字段缺失或为零时回退上传时间 `uppt` / `ptime`；这些远端时间字段及两端比较、对齐精度均为 Unix 秒，并会写入 `SyncFile` 和下载任务。启用“下载元数据”和“检查元数据修改时间”时，远端时间严格较新才会创建替换下载任务，下载成功前保留本地旧文件，本地严格较新且允许上传才会替换远端并创建上传任务。mtime 相等时不计算 SHA1；mtime 不同但大小相同且远端提供 SHA1 时，系统流式计算本地 SHA1，并在哈希前后只复核本地文件的大小与 `ModTime().UnixNano()`。该纳秒值仅用于尽可能发现哈希期间的本地变化，实际精度受本地文件系统限制，不表示 115 提供纳秒级时间。SHA1 忽略大小写比较，相同则不传输、仅将本地 mtime 对齐为远端官方修改时间；文件在哈希期间变化时跳过本轮，SHA1 缺失或计算失败时才回退既有时间方向。下载实际写入成功后也会使用任务携带的远端官方修改时间设置本地 mtime。

元数据更新先写入目标目录中的临时文件，检查预期大小及来源提供的 SHA1 / MD5，并设置文件时间，成功后才替换旧文件。入队时记录旧文件的内容、大小和修改时间；替换前发现本地文件变化则保留当前文件并报告失败。仅补缺的任务不会覆盖已有文件，Webhook 也遵循这一规则。下载或校验失败会清理临时文件，并保留旧文件供使用；发布成功后若来不及保存任务完成状态，重试会核对已发布的内容和时间再收尾。文件替换与数据库状态保存不是同一个事务。 下载任务大小为 0 时只接受空文件；来源缺少大小却返回非空内容时，任务会失败并保留旧文件。没有远端摘要时只能核对大小，不能据此确认内容完全一致。 仅补缺的发布需要文件系统支持 hard link；不支持时任务失败，不退回覆盖写入。进程强制退出可能留下临时文件，程序不会在启动时自动清扫。

下载内容摘要校验只使用来源提供的可信内容摘要。百度列表的 `md5` 是云端哈希，保留在任务中但不参与内容 MD5 校验；首次下载、替换及已有任务重试均遵守此规则。百度下载仍检查预期大小、旧目标基线及发布结果，115 和 OpenList 的可信 SHA1 / MD5 校验保持有效。

创建下载任务前会分页读取当前下载范围中处于 `pending` 或 `downloading` 的任务；范围由 `source`、`source_type`、`account_id` 和非零 `sync_path_id` 组成。每一页都必须先参与远端文件 ID 去重，再判断是否已读取最后一页，避免元数据任务重复入队。临时同步没有 `sync_path_id` 时不能使用该预过滤，最终创建任务会以相同来源、账号和本地目标路径作为范围兜底，避免不同本地目标互相阻塞。该预过滤只用于减少重复查询；创建时由下载队列表的活跃任务部分唯一索引作为并发最终约束，失败任务重试也会避让同一范围内的活跃替代任务。

元数据替换还会在重复摘要计算之前，按来源、账号、同步目录和本地目标检查已有活跃替换。已有安排时继续处理其他文件，不重复入队或计入新增元数据；并发入队命中活跃任务约束也不使整轮同步失败。实际数据库查询失败仍是错误。

本地元数据复制在写临时文件时计算摘要，复制结束后再完整读取源文件复核内容、身份、大小和修改时间，减少一次复制前的完整读取。发布保护按实际父目录和目标文件隔离，符号链接别名指向同一目标时仍互相等待，独立目标可并行；旧目标基线检查及失败保留规则不变。

完整成功的前台结果与保存型目录的 `last_sync_at` 在同一短事务提交；全量成功同时清除 `is_full_sync`。部分完成、扫描不完整、失败或取消均不推进整根成功时间；必要写入失败不广播成功。全量任务在运行中失败或被取消时会保留该标记，使下一次同目录同步仍按全量执行。进程启动时，遗留在待处理或进行中的 `sync` 记录会标记为失败，并把受影响保存型目录的 `is_full_sync` 清回 `false`，避免过期运行态永久阻塞后续操作。

账本按 ID 分页核对和保存差异，边删除边翻页不会跳过后面的记录。每页提交成功后才移除对应缓存；失败页回滚，此前已提交的页保留，后续页停止。这里只更新或删除 `SyncFile` 记录，不扩大本地文件或远端文件的删除范围。批量上限和保留字段见 [`sync_files`](../reference/database-schema.md#sync_files)。

仅已终结（已完成、失败、部分完成、扫描不完整或已取消）的普通记录允许通过用户删除接口删除；定期清理由全局 Cron 在每天 `00:00` 执行，保留期为 7 天，并同时删除关联日志。清理任务可以删除过期的未终态历史记录，因此它不是用户主动删除的替代路径。

## 生成结果与后台账本

前台完成扫描、生成和必要清理后，保存生成结果、数量、结束时间 `finish_at`，并在符合条件时更新目录的最后成功同步时间。随后按原有条件发送一次生成结果通知。通知发送较慢或失败时，后台保存和来源队列仍可继续；后台结束后不再发送第二次正常完成通知。

保存型同步在后台更新账本，也就是用于下一次同步核对文件的 `SyncFile` 记录。后台接管本轮缓存和失败保护信息，前台不再修改它们；前台正常返回不会取消后台工作。后台 SQL 和等待使用独立的服务 context。临时同步和前台失败时无需后台更新，状态为 `not_required`；部分完成或扫描不完整时，仍可更新已确认的文件记录，并保留失败范围内的旧记录。

面向用户的日志和错误说明统一称为“同步文件记录”。开始时记录“开始更新同步文件记录”，结束时按实际结果记录“同步文件记录更新完成／失败／中断”，并保留任务 ID、结果状态和错误原因。这里更新的是下次同步核对所需的文件信息，页面字段文案见 [前端开发约定](../engineering/frontend-development.md)；它不表示重新生成 STRM 或下载元数据。

后台保存失败后，下次同步按新扫描到的文件重新核对，不重放上一次缓存。增量只修复它实际发现的变化，剩余差异等下一次原定全量扫描；不会因后台失败回退最后成功同步时间或额外安排全量。扫描不完整时仍保留受影响的旧记录，不能仅凭账本缺项删除本地文件。

`ledger_status`、`ledger_finished_at` 和 `ledger_error` 分别记录后台状态、结束时间和错误，不改写已经保存的生成结果、生成耗时或目录最后成功同步时间。总耗时从任务的 `created_at` 算到生成和后台保存都已结束的时刻；无需后台保存时等于生成耗时。重叠执行的时间不重复相加，元数据传输、Emby 扫库和刮削的耗时不算在内。字段和历史兼容见 [数据库 schema](../reference/database-schema.md#syncs)。后台结果在列表展开行和任务详情中展示，具体文案与展示范围见 [前端开发约定](../engineering/frontend-development.md)；详情流等后台结束后关闭，来源队列在前台生成结束后即可继续。

应用启动时，将上次仍处于 `pending/running` 的后台任务标为 `interrupted`。不知道实际结束时间时保留空值，不拿重启时间计算耗时，也不额外触发扫描。应用停止时不再接收新的后台任务，取消服务 context，并在关闭日志前最多等待 10 秒；已退出的后台任务另有最多 5 秒保存结果。保存失败会写入日志，不能向页面报告保存成功。停止后才提交的后台任务也会标为中断。

任务日志会等通知、后台保存和下游任务提交都结束后关闭，之后不再写入或重新打开。生成结束后，即使后台尚未开始或仍在运行，用户也可以删除这条同步历史；后台继续保存 `SyncFile`，不能重新创建已删除的记录或日志。状态保存及发布与删除按[实时事件顺序](realtime-events.md)串行，删除事件之后不会再发布该历史的旧状态事件。只有数据库明确确认历史已删除时才跳过状态保存；数据库故障、取消或状态冲突不能当作删除处理。

115 正常同步定位同步根时，将已取得详情中的完整祖先链交给本轮后台账本保存，不额外发起预采集请求。根下文件和目录继续使用 `SyncFile`；同步根自身及根外祖先按同步目录保存在独立根资料中，仅作为位置证明，不加入 STRM 生成或清理范围。空目录、无变化增量和全量都经过根定位，不能依赖后续恰好发生的目录详情请求补链。

根资料绑定来源、账号主体、最终确认的根 ID／路径和真实读取时间。前台扫描结束不代表资料已可用：文件账本成功保存后才发布新根链，后台失败或取消保留旧资料。正常响应已确认根或祖先身份冲突时，立即将旧根资料标记失效；即使后续扫描失败，也不能继续用旧链授权新观察。完整成功后保存新链并解除失效，相关配置或账号已变化则拒绝保存。根资料及文件账本共同计入后台完成时间，缓存命中不伪造新观察时间。

以上资料供 [Emby 本地证据构建](emby-library-sync.md#本地文件和目录资料)使用。目录保存须按根去重，沿用现有批量账本与位置缓存失效机制，不随每个视频重复写入整条祖先链。

## 相互影响的操作如何排队

完整同步、手动生成、上传后处理、Webhook 和刮削写入 STRM 前，会先等待正在处理相同位置的任务。判断依据包括同步目录 ID、同一来源和账号下的远端目录，以及本地输出路径；父目录和子目录也会相互等待。独立刮削任务共享同步目录的配置保护，同时排他保护实际新旧视频和元数据目标，因此同一保存目录内输出互不重叠的影片可并行；配置修改、删除及同目标写入仍须等待。不同账号写同一本地位置时同样需要等待。

本地符号链接按实际位置比较，尚未创建的目录通过已有父目录确定位置。目录在检查期间刚被其他任务创建时会重新确认，避免沿用过时的“目录不存在”结果。输出根本身可以是符号链接；如果根内的子链接把新文件指向本次保护范围之外，会停止该文件的写入并保留旧文件。文件操作的链接无法解析时仍会报错。旧记录指向其他真实位置时，先将该位置一并加入等待范围。

完整同步按位置版本复用进程内的逻辑位置快照，稳定冷构建只遍历一次旧账本，热缓存有效时省去整账本查询；失效后允许重新遍历。每页最多 256 条，只查询尚未检查的记录。位置版本覆盖记录增删、位置及根配置修改、恢复和数据库重置，并与成功提交及范围释放协调；仅大小、mtime、签名或 updated_at 变化不使位置快照失效。构建前后和取得保护后都需核对版本，不能仅凭“没有等待”判断快照有效。单文件生成只检查该文件的旧位置。

跨轮缓存保存逻辑位置，不缓存最终真实路径以跳过符号链接检查。每次申请保护仍重新解析实际位置；最终取得保护后绑定本次真实根，每个目标仍单独解析。根或子链接随后转向未受保护的位置时拒绝写入，不能把绑定根静默改成新位置；重新申请保护时重新绑定。旧文件清理继续使用其独立的允许范围。

等待从读取后续写入所依赖的旧记录之前开始，持续到保存结束或操作失败退出。完整同步在前台结束后，由后台继续保留这段保护，直到同步记录和后台结果保存结束；慢通知和下游任务提交不会延长等待。排队中的同步可以取消，也不会提前暂停上传、下载队列。文件处理仍保留原有并行方式和目标文件锁。

修改或删除同步目录也需要等待相关操作结束。修改路径时，同时考虑新位置和旧记录仍指向的位置；等待结束后重新读取配置，避免沿用排队前的旧路径。已排队的完整同步如果发现路径或账号已变更，会报错并提示重新启动；配置、上次成功时间和全量标记则使用重新读取的值。无法可靠判断范围时，先扩大等待范围，不能猜测两个操作互不影响。范围等待发生在数据库事务之外，一次申请所有需要的位置，避免两项移动操作各占一边、互相等待。

PostgreSQL 的同步目录删除及文件账本批量写事务，还会与 [Emby 快照提交](emby-library-sync.md#物理快照与身份版本)协调来源记录的锁顺序；该数据库保护在事务首次写入之前取得，既有范围等待仍发生在事务外。仅刷新文件时间的批次同样需要协调，不能用“位置没有变化”跳过。

配置修改或删除时，若旧输出根或旧文件记录中的本地路径因断链等原因无法解析，改为全局等待，再允许修正或删除配置；删除配置不删除本地文件。新配置的输出路径仍须通过解析，数据库错误和请求取消仍使操作失败。此例外仅用于配置管理，完整同步、文件生成及生成后的收尾仍保留原有路径检查，不能因配置可修复而提前完成任务或清理源文件。

只读取已提交结果的页面、播放请求和普通 Emby 刷新无需等待整轮同步。删除同步历史只删除 `sync` 记录和日志，也不需要等待后台保存。Emby 联动删除远端文件的等待规则见 [Emby 媒体库同步](emby-library-sync.md#webhook-单条同步)。

## 完成后的协作边界

- 完整保存型同步只有在新增 STRM 或新增元数据下载任务时才请求 Emby 刷新；刷新由协调器延迟执行，具体规则见 [Emby 媒体库同步](emby-library-sync.md)。
- 只有新增 STRM 时才发布关联刮削路径的异步触发事件；没有新增 STRM 时不触发关联刮削。
- 临时同步不参与以上两类下游触发。
- 目录监控、外部 STRM Webhook 和上传完成后的文件级处理使用 `strm_generation_tasks`，不能伪造完整 `sync` 记录或插入同步目录队列。

## 不变量

- Cron 和 HTTP 入口只能入队，不能绕过按来源队列直接执行完整同步。
- 同一来源、同一保存型同步目录、同一任务类型在等待或运行期间只能有一个内存任务；跨来源队列不共享该去重范围。
- `sync` 记录是完整同步的审计与实时状态来源；上传后或 Webhook 的单文件 STRM 后处理不得创建伪造的完整同步记录。
- `is_full_sync` 只能由全量入口置为 `true`；成功完成后清除，运行中失败或取消时保留给下一次重试，启动恢复处理遗留运行态时清除。
- 停止同步是取消信号，不是伪造“已完成”状态；最终状态必须由执行器写入记录。
- 115 元数据的比较、下载任务和本地时间回写都使用同一官方修改时间；上传时间只可作为缺失修改时间的兼容回退。
- 内容相同的元数据不因秒级 mtime 差异传输；哈希期间本地文件发生变化时不得上传、下载或覆盖该文件。
- 已确认失效的视频版本，其远端也缺失的专属 NFO、图片不得作为新增元数据回传；共享元数据、存活使用者和受保护范围不得被该规则扩大清理。
- 单文件生成不能绕过名称及父目录排除；正则匹配使用原始大小写，原有完整匹配仍忽略大小写。

## 验证方式

- `TestLocalMetadataUpload*` 和 `TestOpenListMetadataUploadPreservesPaths` 验证根目录、结尾分隔符、多层目录、合法点及空格、同轮新建目录和重复同步，核对最终上传任务、本地实际复制位置与 OpenList HTTP 上传及详情路径。`TestLocalDriverCreateDirRejectsInvalidPath` 验证相对路径或越界输入不创建目录。运行 `go test ./internal/syncstrm ./internal/models`，相关用例同时运行 `-race` 和 `go vet`。
- 运行 `(cd backend && go test ./internal/synccron/)`，覆盖按来源队列、去重、暂停、恢复、取消和状态输出。
- 运行 `(cd backend && go test ./internal/models/ -run 'Test.*(Sync|Delete)')`、`(cd backend && go test ./internal/syncstrm/)`，覆盖记录状态、启动恢复、执行和下游触发边界。
- `syncstrm` 的 115 上传父目录与目录列表回归覆盖完整列表免补查、空目录上传、删除／移动／改名、同名新 ID、空查询补查、电视剧层级、附属目录创建、分页与身份冲突；同时核对实际本地文件、账本、扫描状态及请求计数。`v115open` 的路径详情回归区分成功空数组、正常详情、明确不存在和异常响应。`sync_others_directory_failure_test.go` 继续保护百度全量移动目录读取失败后的旧、新子树、兄弟清理及账本错误。相关测试运行普通测试、`-race` 和 `go vet`。
- `TestLocalMetadataCleanup` 回归覆盖电影与单集多版本、同名及带后缀图片、文件遍历顺序、共享元数据、同 stem 存活容器、受保护视频、活跃上传与重复同步；同时核对上传任务和查询计数，关联判断不增加网盘请求或历史账本读取。
- 旧 ID 查询返回 `430004` 后，父目录列表返回授权失效或 HTTP `401`，必须保留认证错误并停止本地核对，后续兄弟目录的 STRM 不得继续删除；普通补查失败仍只保护受影响范围。
- 排除回归覆盖完整名称、正则、祖先目录、单个元数据文件、源视频名称与当前／旧输出位置的本地 STRM 名称，验证本地 STRM、元数据、空目录和旧账本保留，独立兄弟继续处理，跳过不使同步失败。真实 115 驱动和 HTTP 替身验证目录及文件排除在缓存有无时都不触发上传补查、建目录或上传任务；新一轮远端扫描不为排除项生成 STRM 或下载任务。
- 已存在附属目录的回归分别使用路径详情和本轮确认信息，验证直接复用 ID、零创建请求；非排除路径继续验证缺少目录证据时拒绝创建，以及宿主存在时正常补建缺失附件目录。
- 修改 Cron 注册或同步目录聚合保存时，运行 `(cd backend && go test ./internal/syncconfig/)` 与相关控制器测试；在测试环境检查修改 `enable_cron` 或 `cron` 后旧计划已停止、新计划仅注册一次。
- 配置失效路径回归运行 `models`、`syncconfig` 中的 `TestDeleteSyncPathWithUnresolvableOldLocation`、`TestSaveSyncPathWithUnresolvableOldLocation`，覆盖旧根及旧账本断链、全局等待、取消保留记录、删除保留本地文件和新路径严格校验；同时运行 `syncstrm` 的 `TestGenerationFinalizingScopeFailureRetry` 与符号链接范围测试，确认文件操作仍拒绝失效或越界路径。
- 修改排除规则时运行 `(cd backend && go test ./internal/syncstrm/ -run 'Test(ValidFileHonorsNameAndParentExclusions|RegexExclusionMatching|NewSyncStrmRejectsInvalidRegex)')`，验证完整匹配兼容、正则大小写及父路径排除。
