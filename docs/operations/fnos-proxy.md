# 飞牛影视反代运维

> 职责：说明飞牛影视反代的启用、路径、证书、网络和故障处理。
>
> 权威范围：本文档维护部署与操作边界；API、运行字段和接管安全契约见 [飞牛影视反代 API](../reference/fnos-proxy-api.md)，数据结构见 [数据库 schema](../reference/database-schema.md#fnos_proxy_config)。
>
> 修改时机：修改页面入口、启用方式、证书路径、监听、保存生效时机或排障流程时必须同步更新。
>
> 相关代码：`backend/main.go`、`backend/internal/fnosproxy/`、`frontend/src/components/AppFnosProxySettings.vue`、`frontend/src/components/fnos-proxy/FnosPathMappings.vue`。

## 范围与默认行为

飞牛影视反代在独立端口透传飞牛影视，并在可靠识别 STRM 后复用 QMediaSync 现有取链与播放策略。当前接管覆盖 Emby 兼容协议，以及飞牛影视 0.9.8 原生网页的 STRM 直播放接口；其他版本和手机／电视客户端仍需实测，不承诺所有取流方式效果一致。

飞牛账号被禁用、禁止播放或要求远程来源转码时，反代不强行改为直播放；下载入口还遵守禁止下载设置。飞牛影视 0.9.8 的部分客户端请求方式可能返回原网页而非播放信息，本功能保持上游响应，不补造协议支持。排障时应同时核对账号策略与客户端请求方式，具体版本和 ID 契约见 [播放接管与回退](../reference/fnos-proxy-api.md#播放接管与回退)。

功能默认关闭，无额外飞牛监听或专用后台监控。不开启时无需调整原有 Emby302、同步、刮削和播放配置。飞牛配置独立保存在数据库，不新增 YAML、环境变量、管理员代登录或媒体库扫描设置。

## 启用与确认

1. 确认 QMediaSync 能访问原飞牛影视服务，且可以读取对应 STRM 文件；Docker 需额外挂载文件目录。
2. 打开「系统设置 → 飞牛影视」（`/settings/fnos-proxy`），开启「启用反代」，填写原飞牛影视根地址。地址不能指向反代自身、QMediaSync 主站或 Emby302；不要填播放器代理域名。
3. 同路径的已知输出可先不填写映射；路径不同或使用其他输出目录时，按下一节声明对应根。
4. 点击保存，程序先入库再立即应用飞牛模块，无需重启 QMediaSync。HTTP 固定为 `9005`，HTTPS 自动检测证书后使用 `9006`，页面没有端口或 HTTPS 开关。
5. 查看页头的轻量运行状态，以及保存按钮附近的结果提示。保存区只保留按钮，不显示附加说明或外框；状态区保留必要的错误／未应用原因，不提供连接地址示例或“已保存配置”行。“已保存”与“应用成功”不同。
6. 在浏览器打开反代入口，或在兼容播放器中填写该入口，用原飞牛影视账号登录，核对 STRM 播放、非 STRM、字幕和拖动进度。

启停、上游或映射变化会重建飞牛模块，中断该模块当前播放和 WebSocket，并清空来源缓存；不会重启主站或 Emby302。同一健康配置重复保存不重建。数据库写入失败保留原运行服务；已保存但应用失败时显示警告与实际状态，修正原因后再次保存重试。新实例的校验或传输构造失败发生在停止旧实例前，旧实例仍可能运行，但不能视为新设置已运行；进入切换后失败不自动回退旧配置。遗留状态字段 `restart_required` 在这里表示配置未应用，应结合 `last_error` 查看原因，不要求普通保存后重启。

新增或替换证书仍需重启 QMediaSync；数据库恢复也继续按原维护流程重启，普通保存不能解除恢复维护。Docker Compose 使用实际服务名重启，systemd 使用对应服务，Windows 退出后重新启动，fnOS 在应用中心停止再启动。此页面不借用数据库恢复专用的重启回执接口。

设置页进入和保存后读取状态，不新增 SSE 或定时诊断面板；必要错误写入现有主程序日志，用户沿用日志页面和部署日志查看。

## 路径映射

同一份文件可能在飞牛与 QMediaSync 中有不同路径：

```text
飞牛影视： /vol1/media/strm/电影/示例电影.strm
QMediaSync：/media/strm/电影/示例电影.strm
```

增加一条 `/vol1/media/strm → /media/strm` 即可保留后面的相对路径，不需要逐片配置。QMediaSync 一侧复用本地目录选择器，也可手动输入；飞牛一侧按飞牛实际路径填写，不使用本地选择器猜测远程路径。选择只修改当前表单，主页面保存后才入库；取消不清空原值。

映射只帮助读取本地 STRM，不改文件、播放 URL 或媒体库路径，也不授予删除权限。两端应指向同一份目录内容；没有挂载或读取权限时，映射不能补齐这些条件。显式映射优先，映射不可读不会转去别处找同名文件。无映射时只尝试可信输出根的相同路径，或有可靠来源身份且唯一确认的有限候选；只有相似路径或同名不能自动换根。

Docker 中 `local_root` 为容器内路径。fnOS 原生安装需要为 QMediaSync 应用授权目标目录；不因服务安装在同一 NAS 就默认可读全部文件。

## HTTP 与内置 HTTPS

HTTP 固定监听 `9005`，主机部分继承主站 `httpHost`；HTTPS 固定使用 `9006`，主机部分继承 `httpsHost`。未启用飞牛则都不监听；启用后先建立 HTTP，下面的证书与私钥两文件均存在时自动尝试额外的 HTTPS，两者共用实例，不自动把 HTTP 跳转为 HTTPS。

内置 HTTPS 复用主站的证书文件：

```text
<程序根目录>/config/server.crt
<程序根目录>/config/server.key
```

证书和私钥须匹配、允许 QMediaSync 进程读取，证书需适用于播放器使用的域名。Docker 通常对应 `/app/config/`；fnOS 原生包中程序根目录与业务共享配置目录可能不同，证书跟随主站 `RootDir/config`，不是随意放入业务共享目录。Emby302 仍读取自己的 `ConfigDir`，此次不统一或迁移旧路径，也不能把整个根 `config/` 软链接到共享目录。

缺任一文件时只运行 HTTP。两文件存在但不可读、证书密钥不匹配，或 HTTPS `9006` 绑定失败时，只关闭 HTTPS 并报告错误，HTTP `9005` 继续提供服务；HTTP 本身绑定失败才使飞牛模块停止。启动读取已存配置与网页保存共用保留端口校验；若固定端口与主站或 Emby302 的配置端口冲突，飞牛模块在绑定前拒绝启动并报告原因，为主站和 Emby302 保留监听端口。主站和 Emby302 继续各自运行。运行状态正常只证明服务已监听，不证明客户端信任证书、域名匹配或证书未过期。

不提供证书上传、自动申请、续签、私钥入库、监控或热加载。新增或更换证书后重启 QMediaSync；同一健康配置重复保存不会为了重读证书而打断播放。已有 HTTPS 错误的实例可在修正问题后再次保存重试。

飞牛上游地址的 HTTP／HTTPS 与客户端入口独立。上游 HTTPS 默认校验证书，不能通过 Emby 的 `insecure_skip_verify` 放宽；需要自签证书时按受信证书部署处理。

## 容器端口与外部反代

内置端口固定，容器、路由器和防火墙不会随网页保存自动修改。Compose 可增加 `"9005:9005"`，也可以用 `"19005:9005"` 让宿主机 `19005` 对应容器 HTTP `9005`；此时播放器访问宿主机端口 `19005`。使用内置 HTTPS 时按需增加如 `"9006:9006"` 的发布。保留现有配置和挂载，只增加实际使用的端口，不整份覆盖部署文件。

外部反代使用独立子域名和完整根路径，上游为飞牛反代 HTTP 端口；不复用管理站子路径，也不把上游误填成原飞牛服务而绕开 QMediaSync。Nginx 需要支持 WebSocket 升级、长连接、Range 和流式响应；代理不缓存带身份的播放信息或跳转。Caddy 的最小站点示例：

```caddyfile
video.example.com {
    reverse_proxy 127.0.0.1:9005
}
```

域名和上游替换为实际值；宿主机端口映射不同时使用实际发布端口，若代理在其他容器中则使用其可达的服务名和容器端口，不使用容器自身的 `127.0.0.1`。HTTPS 在外部结束时，直接回源 HTTP 即可，无需使用自动附加的内置 HTTPS。QMediaSync 管理站仍沿用 [同源、可信代理和 SSE 配置](reverse-proxy.md)，不为飞牛新增管理 SSE 路由。

## STRM 地址与缓存

路径映射解决的是服务端读取文件。对于已确认属于当前实例的 STRM URL，即使文件里写的是播放器不能访问的内网 QMediaSync 地址，也会内部转交现有取链入口，继续使用原来的 UA、缓存、多端播放和支持的流代理策略。

外部 OpenList `/d/...` 或其他外部 HTTP URL 仍按原地址跳转；最终 CDN 也须对播放器可达。内部转交不等于任意外部私有地址都被代下载，服务器能访问也不代表播放器能访问。

原生网页先向飞牛提交原始播放请求，飞牛按当前会话验证签名和播放许可。QMediaSync 只在成功响应中的文件、STRM 路径与内容均能核对时，内部取链并替换该次直接播放地址，保留飞牛返回的实际播放 UA、字幕和其他播放选项。无需保存飞牛管理员账号，也不修改网页脚本。取链失败、文件不可读、非 STRM 或未知播放方式继续保留原响应，具体规则见 [原生网页播放](../reference/fnos-proxy-api.md#原生网页播放)。

来源缓存只在当前进程内保留，固定 24 小时到期、最多 256 条，不新增设置或表。每次接管仍检查当前飞牛权限、媒体源和文件状态。更换 STRM 通常在下一次请求重新核验；原地改内容又恢复相同元数据可能要等固定到期后才重读，不做实时目录监控。停止或重启会清空来源缓存；网盘最终直链仍由原有取链缓存负责。

希望减少点击播放时的等待，可在 [STRM 设置](configuration.md#strm-预加载) 开启全局“启用 STRM 预加载”；飞牛设置只提供跳转。成功详情的当前项在停留约 2 秒后准备链接，优先复用同一已认证设备的有效播放 UA 映射，首次访问、重启或控制端版本更新时使用本次请求的合法 UA；本地代理使用原固定有效 UA。预测与实际播放器不同时，真实播放仍按自己的 UA 查原缓存或正常取链，不跨 UA 借用链接；可能多一次预热或进入既有副本流程。原生裸播放记录缺少可靠暂停／会话，当前不用于下一项预加载，原生分段关系也不凭文件名推断。兼容入口按能核验的源、进度和后继处理，精确边界见 [预加载观察与限制](../reference/fnos-proxy-api.md#预加载观察与限制)。Apply／停止、权限或配置失效均撤销旧实例后台，后台不重放原生签名、不下载视频或改写进度。

## 排障与迁移

| 现象 | 检查与处理 |
| --- | --- |
| 已保存但提示未应用，或 HTTP 未运行 | 查看实际错误，排除固定端口 `9005` 占用等原因后再次保存；不要把警告当作数据库保存失败 |
| 端口绑定失败 | 释放占用 `9005`／`9006` 的其他程序，或调整宿主机端口映射、防火墙；宿主机映射不会改变容器内固定端口 |
| HTTP 运行但 HTTPS 未运行 | 缺任一证书文件时是仅 HTTP；若有错误，核对证书、读取权限及 `9006` 占用。修正已有错误后可再次保存；健康实例新增／换证书需重启 |
| HTTPS 浏览器或播放器报证书错误 | 核对访问域名、完整证书链、有效期及客户端信任，不关闭上游证书校验代替修复 |
| 能登录但 STRM 没被接管 | 核对客户端／飞牛版本、账号播放设置、准确媒体源、同一文件的两端路径、挂载和权限；下载还核对禁止下载。原生接口返回业务失败、网页或未知格式时仍透传 |
| 兼容接口有媒体总数但列表为空 | 查询媒体库时带上 `ParentId`、非空 `Fields` 和正数 `Limit`；季和单集使用对应的 Shows 接口，详见 [兼容列表查询](../reference/fnos-proxy-api.md#兼容列表查询) |
| 暂停、退出正常，但重开仍从头播放 | 先检查飞牛识别的媒体时长。本次样本的进度已保存，但飞牛返回时长为 0，网页把保存进度限制为 0 后从头播放；浏览器仅临时修正时长即可续播。应处理飞牛的时长识别，不通过重复改映射或补造进度解决；反代保持进度接口透传 |
| 能取链但不能播放 | 在实际播放器网络检查外部地址或 CDN；不要仅用服务端探测判断可达 |
| 恢复数据库后入口不可用 | 按恢复结果重启，再检查启用状态、映射、挂载和证书；普通保存不解除恢复维护。旧 schema 备份没有飞牛配置，恢复后默认关闭 |
| 需要定位原因 | 查看现有日志，反馈版本、客户端、错误时间和脱敏路径；不分享 Token、Cookie、私钥或完整签名 URL |

数据库备份包含飞牛启用状态、上游和映射，不包含来源缓存、证书、STRM 文件或目录授权；迁移需另行准备。恢复新版配置后按保存内容启动，目标缺证书时仅提供 HTTP；旧包适配和 schema 规则见 [数据库运维](database.md#恢复与风险边界)。
