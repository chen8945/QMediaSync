## 配置文件与默认端口

- 主配置为 `config/config.yaml`，兼容旧 `config.yml`。首次启动缺少主配置时会启动配置向导，当前可选择 SQLite 或 PostgreSQL，保存后生成 `config/config.yaml`。
- Web 默认端口：HTTP `12333`、HTTPS `12332`；Emby 302 代理默认端口：HTTP `8095`、HTTPS `8094`。
- 完整字段示例见 [config.yaml](../examples/config.yaml)。示例仅说明字段，运行时以 `config/config.yaml` 为准。
- 默认数据库配置为 PostgreSQL。使用 PostgreSQL 时，应单独部署 PostgreSQL 15 及以上，并填写 `db.postgresConfig`；应用二进制和 Docker 镜像均不携带或启动 PostgreSQL 服务。
- 新配置不再写入 `postgresType`。旧 PostgreSQL 配置中的 `external` 或缺省值均可继续使用；显式 `embedded` 会被拒绝。旧库和未完成迁移包的处理边界见 [数据库运维](database.md#旧内嵌数据库)。
- 数据库连接信息只从主配置读取，旧 `DB_HOST`、`DB_PORT`、`DB_USER`、`DB_PASSWORD`、`DB_NAME`、`DB_SSLMODE` 环境变量不再作为数据库配置入口。
- 数据库引擎、备份恢复和修复操作见 [数据库运维](database.md)；表、版本和迁移语义见 [数据库 schema 与迁移](../reference/database-schema.md)。

fnOS 原生包同样使用上述通用生成和保存逻辑，安装脚本不生成或覆盖业务 YAML，`log`、`jwtSecret` 和本机加密密钥不另设平台默认值。主配置、SQLite、日志和密钥使用应用共享目录下的 `config/`；已有共享配置优先，旧目录冲突保留并报告，见 [fnOS 部署](deployment.md#飞牛-fpk)。程序根目录的 `config/` 还含平台权限和资源声明，不能整体软链接到共享目录；`.env` 与 HTTPS 证书继续使用根目录规则。

主配置和内嵌 Emby 302 配置统一使用 `go.yaml.in/yaml/v3`。主配置中解码到布尔字段的 `yes` / `no`、八进制数字、锚点合并和保存后回读保持兼容；非法合并键返回解析错误。

同一映射内的重复键会被拒绝，包括嵌套字段；不再采用旧主配置解析器的“后值覆盖”行为。遇到重复键时按错误行号修正配置，再启动程序；解析失败不会自动覆盖原文件，也不会退回读取旧 `config.yml`。正常配置无需预先改写，程序下次保存时使用 v3 默认的 4 空格缩进。

管理员恢复使用二进制参数 `--reset-admin-password` 或 `--delete-admin --yes`，可通过 `--config-dir` 指定已有配置目录；这些参数不能写入长期运行的服务配置，不新增 YAML 字段。恢复只读取配置，不补写默认 JWT 密钥或本机加密密钥。操作命令和 Compose 自动识别规则见 [管理员恢复](deployment.md#管理员恢复)。

## 网页设置与应用边界

刮削服务、出站代理、线程组、通知渠道和 Emby 连接配置保存在数据库。成功保存并完成本地应用后，后续请求或任务在当前进程使用新配置，无需重启。已进入的同步、刮削、上传和 Emby HTTP 流／WebSocket 保留各自进入时的快照；HLS 后续分片属于新的请求。保存不会自动重写已生成的 STRM、文件名或图片地址。

### 保存与发布的不变量

数据库提交前沿请求上下文处理取消，提交失败时保留旧有效配置；提交成功后，即使浏览器取消也完成对应发布与本地应用。本地应用失败保留已保存值并返回成功包络的顶层警告，可重新保存相同设置重试；字段结构见 [公共响应契约](../reference/api-response.md)。配置回读失败与保存、应用结果分别处理。恢复维护等待已接受的设置命令及应用完成后再替换数据库，具体顺序见[恢复边界](database.md#恢复与风险边界)。

此边界不包含主配置 YAML、`.env`、数据库连接、主站监听地址或证书文件的自动重载；相应运行步骤仍按各自运维说明执行。

### 验证方式

设置保存、后续行为、并发发布及恢复许可运行[网页设置应用验证](../engineering/verification.md#网页设置应用验证)。

## 飞牛影视反代

「系统设置 → 媒体库 → 飞牛影视」只配置启用开关、独立飞牛上游和 STRM 根映射，保存在数据库，不向 YAML 或环境变量增加同名字段。默认关闭，保存后立即应用飞牛模块，无需重启主站；配置变化会中断本模块当前播放和 WebSocket，健康同配置重复保存不中断。不使用时无需调整原有 Emby302、同步、刮削或取链配置。

HTTP `9005`、HTTPS `9006` 固定，主机部分继承主站对应监听地址。主站 `RootDir/config/server.crt` 与 `server.key` 均存在时自动尝试 HTTPS，缺任一文件仅 HTTP，HTTPS 错误不停止 HTTP；fnOS 下证书位置不等同于 Emby302 的 `ConfigDir`。新增或替换证书仍需重启，不新增自动证书管理或跳过上游证书验证选项。具体设置、应用失败重试和部署统一见 [飞牛影视反代运维](fnos-proxy.md)，接口与缓存规则见 [飞牛影视反代 API](../reference/fnos-proxy-api.md)。

## STRM 列表与继承

视频最小体积和全局定时同步表达式由网页「STRM 同步 → STRM 设置」保存到数据库；同步目录可另设自定义规则。主配置中的 `strm.minVideoSize`、`strm.cron` 是历史字段，加载时会无条件重置为 `100` 和 `30 * * * *`，不能通过修改这两个 YAML 值调整网页设置。扩展名列表的回退规则如下，不能把这两个字段的行为类推到所有 `strm` 配置。

全局 STRM 设置和同步目录自定义设置管理视频扩展名、元数据扩展名、排除名称和正则排除名称四个列表。目录中每个列表独立决定是否继承：非空列表覆盖相应全局列表，空列表继承相应全局列表。

目录表单的“导入全局设置”保留当前条目，按全局列表顺序追加尚未包含的条目。扩展名和普通排除名称按不区分大小写去重；正则只对完全相同的原文去重，不裁剪空白、改变大小写或拆分表达式。导入是一次性合并，保存非空列表后不再随全局变化；清空并保存可恢复继承。

全局和目录表单均为每个列表提供“清空”，确认后只修改当前表单中的相应列表及其输入草稿，点击页面保存才会持久化。

| 清空位置 | 保存后的效果 |
| --- | --- |
| 目录自定义的任一列表 | 恢复继承相应全局列表 |
| 全局视频或元数据扩展名 | 使用 `config.yaml` 中 `strm.videoExt` 或 `strm.metaExt` 的默认列表；配置文件中也为空时使用程序内置默认值 |
| 全局排除名称或正则排除名称 | 不启用对应类型的排除规则 |

全局扩展名清空后仍识别默认扩展名，不表示关闭视频或元数据识别。重新打开全局设置时显示生效的默认列表；数据库中的空列表仍保留，保存失败不会替换内存中的旧设置。

## STRM 名称排除

STRM 名称排除保存于数据库，由全局 STRM 设置和同步目录自定义设置管理，不增加 `config.yaml` 或环境变量字段。

| 设置 | 匹配方式 | 大小写 |
| --- | --- | --- |
| 排除名称 | 完整匹配名称，保留原有行为 | 不区分大小写 |
| 正则排除名称 | Go `regexp` 语法，默认部分匹配；使用 `^…$` 限定完整名称 | 默认区分，使用 `(?i)` 忽略 |

完整同步、网盘文件管理手动生成、上传后处理和 Webhook 以文件名（包含扩展名）及路径中的各级目录名为匹配对象；两类规则任意一项命中即排除，目录命中时排除其下内容。正则不跨路径分隔符匹配，表达式和待匹配名称都保留原始大小写。输入采用原始表达式，例如 `(?i)^extras$`，不使用 JavaScript 的 `/abc/i` 包装格式。

完整 STRM 同步中，排除规则优先于缺失元数据的处理选项及附属目录上传白名单，命中后正常跳过。已有本地文件及同步记录的保护、目录查询和已排队任务的边界见 [同步调度](../architecture/sync-orchestration.md#范围和对象)。

两类排除规则都为空时，不按名称排除文件或目录，但 115 多端播放保留目录仍会跳过。普通名称列表为空时，只检查正则；正则始终匹配原始名称。

两类列表的继承和编辑规则见 [STRM 列表与继承](#strm-列表与继承)。网盘文件管理的手动生成直接使用全局配置，单文件生成同样检查文件名和父目录。每次创建同步器时编译正则。完整同步保留本轮配置；上传和 Webhook 后处理的修改从下一小批生效，见 [后处理配置何时生效](../architecture/upload-and-strm-processing.md#后处理配置何时生效)。

规则通过现有保存接口由后端最终校验，正则原文落库。字段及升级行为见 [数据库 schema 与迁移](../reference/database-schema.md)，目录保存契约见 [同步目录聚合 API](../reference/sync-path-api.md)。

前端每次按 Enter 或点击“添加”加入一条完整正则，不按逗号或分号拆分，也不裁剪首尾空格。“常用正则示例”可展开查看：

| 表达式 | 用途 |
| --- | --- |
| `sample` | 排除名称中包含小写 sample 的文件或目录 |
| `(?i)(sample\|trailer)` | 排除名称中包含 sample 或 trailer 的内容，忽略大小写 |
| `(?i)^extras$` | 完整匹配 extras 名称，忽略大小写 |
| `(?i)^sample\.[^.]+$` | 匹配 sample 加扩展名，忽略大小写 |
| `^\.` | 匹配以点开头的名称 |

浏览器会预检格式并提示明确不兼容的语法；遇到无法可靠预检的 Go 语法时允许添加，保存时再由服务器判断。前后端校验的具体边界见 [请求校验约定](../engineering/request-validation.md#strm-正则预检)。

## 上传队列并发

「系统设置-接口速率」中的“同时上传任务数”保存为数据库 `settings.upload_threads`，默认 `1`，允许 `1` 到 `10` 的整数。它控制同时处理的上传任务数；文件准备、秒传等待、传输和完成处理都占用一个名额，不是每秒请求数，也不单独增加上传缓冲区配置。

保存后按[网页设置的应用边界](#网页设置与应用边界)更新后续派发，无需等待整批队列结束：

- 增加数量时，后续任务可以使用新增名额。
- 减少数量时，在途任务继续完成；实际并发降到新限制以下后才补入新任务，因此短时间内可能仍高于新值。
- 队列已暂停时，保存不会恢复队列；手动恢复后使用新数量。

同组的 `openlist_qps` 仍表示 OpenList 接口同时执行的请求数，页面标为“OpenList 接口并发数量”；本次不改变字段名或新增每秒速率限制。

多个上传任务继续复用现有网盘客户端和限速机制；115 请求共用全局请求队列，上传并发数不会倍增其 QPS。下载并发和请求速率仍由 `settings.download_threads` 同时控制；保存线程组任一字段不会重建队列或解除暂停。领取、收尾和暂停边界见 [上传队列执行](../architecture/upload-and-strm-processing.md#上传队列执行)。

## 115 运行参数

- 首页「115 接口监控」的请求数、QPS、QPM、QPH、平均响应时间和限流次数来自 `request_stats` 表，重启后仍按时间窗口聚合展示。
- 115 请求完成后只把统计记录放入有界内存队列，由固定 worker 每最多 32 条或每 500 毫秒批量写入 `request_stats`；队列容量为 2048，写入压力过高时会丢弃非关键统计并在关闭时记录丢弃数量，不阻塞 API、同步、上传或 Emby worker。统计展示因此属于尽力而为，数据库关闭前会尽量刷完已接收记录。
- 「系统设置-接口速率」保存 `file_detail_threads` 后会立即更新进程内 115 请求队列；换算后的 QPS、QPM、QPH 对后续请求生效，不需要重启服务。正在处理或已经入队的请求不保证继续使用旧配置。
- 当前是否限流、等待时间和剩余时间来自进程内 115 请求队列管理器。限流暂停时长为 1 分钟，重启后恢复为未限流。
- 秒传等待策略保存于 `settings`，由 `upload_rapid_wait_interval_seconds`、`upload_rapid_wait_timeout_seconds`、`upload_rapid_wait_min_size`、`upload_rapid_wait_force_size` 和 `upload_rapid_wait_skip_upload` 控制。间隔只控制重试频率，超时字段才是最大等待上限。
- 115 直链缓存有效性检查保存于 `settings`，默认开启，默认总超时为 3 秒、范围为 1 到 9 秒。它只影响缓存 URL 的 HEAD 检查；百度网盘和 OpenList 不使用这套机制。
- 上传协议、目录监控、断点续传、远端已存在和 STRM 后处理的状态边界见 [上传与 STRM 处理](../architecture/upload-and-strm-processing.md)。

## STRM 预加载

在「STRM 同步 → STRM 设置」开启“启用 STRM 预加载”并保存，可提前准备播放链接，减少点击播放和接着看下一集时的等待。开关默认关闭，位于“启用 115 多端播放”上方；「系统设置 → 媒体库 → 飞牛影视」提供到同一设置的跳转，不另存一份开关。

该设置是全局数据库字段 `settings.strm_preload_enabled`，只接受 `0`／`1`，不增加 YAML、环境变量或同步目录覆盖。现有 `GET/POST /api/setting/strm-config` 返回／保存此字段；旧客户端省略或传 `null` 时保留原值，显式 `0` 关闭。保存成功立即生效，无需重新生成 STRM 或重启；关闭会取消待处理和在途预加载，已经有效的缓存仍可用于正常播放。

必须通过 QMediaSync 的 Emby 302 或飞牛反代入口访问。电影、单集详情只准备当前项；剧集／季页只选择一集，可靠进度临近结束时可准备下一集或明确的下一分段。普通电影不找下一部。快切详情会合并请求；首次访问也会尝试准备，缺少可靠来源或权限时跳过。更换播放器可能无法复用已准备的链接，实际播放继续按原流程取链。开启后会增加少量网盘请求，不承诺固定提速或所有客户端有效。精确触发、节流、重试与支持边界统一见 [预加载契约](../architecture/upload-and-strm-processing.md#strm-播放链接预加载)。

支持 QMediaSync 自有 115／百度取链接口，以及其他程序生成的 HTTP(S) STRM；OpenList 等第三方服务按通用跳转解析处理，无需逐个适配或补填 QMediaSync 专用参数。Docker 内网地址也可使用，前提是 QMediaSync 能访问该服务。第三方预加载会以小范围 GET 跟随到最终视频服务，提前准备的结果与正式播放共用，并按完整 UA 隔离；不会下载完整视频。当前用户已授权的明确播放源即可参与，不要求提前探测媒体信息或先播放一次。仅有本地路径且无法通过现有安全流程确认链接时仍跳过。

## 115 多端播放

「系统设置-STRM 设置」的“启用 115 多端播放”保存为全局数据库字段 `settings.multi_playback_enabled`，默认关闭，不增加 YAML、环境变量或同步目录覆盖配置。开关位于“启用本地代理播放”上方。

开启本地代理后，多端播放开关置灰并保留、提交原值；关闭本地代理后恢复编辑。后端根据实际请求模式智能跳过：`local_proxy=1 && force=0` 是代理请求，不复制；内置 Emby 302 使用的 `force=1` 仍为直链，按已保存的多端播放开关判定。因此置灰不表示强制直链请求也被关闭。

不同 UA 的直链请求需要时会在对应 115 账号的 `/多端播放/qms-<随机操作标识>` 子目录复制文件，以副本获取独立链接；根目录固定，不提供位置设置。相同 UA、相同模式继续复用缓存。关闭功能后，已生成的链接按原期限继续使用，已安排的播放后延迟清理继续执行；后续每小时播放维护停止，暂停根目录定位、目录枚举、回收站扫描和失败清理重试。历史残留在重新开启后的下一次整点维护中处理，已开始的维护不因中途关闭开关而取消。

需要副本隔离时，失败会保留已播放端的链接并结束本次取链，不回退原文件。每份副本最多取链两次；明确确认副本不存在时，可重建一次，仍受原 10 秒总预算限制。副本隔离不保证增加网盘允许的下载连接数，具体失败与清理边界见下述架构契约。

槽位依据 URL 缓存期限和在途请求推断，不检测真实设备或播放会话。操作结束后延迟清理整个子目录，异常残留由功能开启时的每小时维护回收；归属已核验的回收站操作目录也会在维护时永久删除，不按缓存到期判断播放结束。程序不在启动时清空根目录，也不清空整个账号回收站。该目录子树从 115 同步、手动 STRM 生成及刮削中排除。完整分配、清理条件和失败边界见 [115 多端播放链路](../architecture/upload-and-strm-processing.md#115-多端播放链路)。

## 媒体服务器连接

“系统设置 → 媒体库”在 `/settings/media-library` 提供 Emby、Jellyfin、飞牛影视三个标签。旧 `/settings/emby`、`/settings/jellyfin` 和 `/settings/fnos-proxy` 分别转到对应标签并保留查询参数。Emby 与 Jellyfin 各连接一台服务器，分别保存到 `emby_config` 与 `jellyfin_config`，可以同时启用；飞牛反代配置保持独立。

两端总开关 `enabled` 新配置默认关闭；关闭保留连接、功能与表单草稿，阻止本端后续同步、刷新、Webhook 业务和提取，另一端继续工作。执行按钮使用本端已保存的设置；总开关关闭时仍可查询媒体库来准备配置。升级已有 Emby 配置时总开关与媒体通知开启，其余原连接和功能设置保留，Jellyfin 不继承。原来在 Emby 地址填入 Jellyfin 的用户需手动改到 Jellyfin 标签，不能继续用它作为 Emby 代理上游。

| 设置 | API／数据库字段 | 行为 |
| --- | --- | --- |
| 地址／密钥 | Emby：`emby_url`／`emby_api_key`；Jellyfin：`jellyfin_url`／`jellyfin_api_key` | 必须可从 QMediaSync 访问，可包含反向代理子路径；密钥在对应媒体服务器创建 |
| 启用本端 | `enabled` | 控制本端全部媒体业务准入，不清空配置 |
| 发送媒体通知 | `enable_media_notification` | 只控制本端向已有通知渠道发送媒体事件 |
| 入库后提取媒体信息 | `enable_extract_media_info` | 只控制新增媒体自动入队；手动提取及已入队任务仍可按总开关与权限执行 |
| 同步后刷新媒体库 | `enable_refresh_library` | 成功的 STRM／元数据变化提交本端刷新，先同步条目建立关联 |
| 启用媒体同步 | `sync_enabled` | 控制本端定时与手动条目同步；手动全量还需总开关启用并通过单独按钮启动 |
| 媒体库范围／周期 | `sync_all_libraries`、`selected_libraries`、`sync_cron`、`enable_daily_first_full_sync` | 分别保存；选库限制本地索引扫描，不限制手动提取的全媒体库扫描 |
| Webhook 认证 | `enable_auth` | 默认启用，使用 QMediaSync API Key；它与媒体服务器 API Key 不同 |

两端保存使用各自配置接口，只做本地校验，允许服务器暂不可用时离线保存。省略字段、显式零值与读取／保存响应契约见 [请求约定](../engineering/request-validation.md#媒体服务器配置与提取)。提交后的应用警告和配置回读失败分别提示，同设置再次保存可重试应用；Emby 代理的请求和连接边界见[独立配置与入口](../architecture/emby-library-sync.md#独立配置与入口)，Jellyfin 不提供代理设置。

关闭 Emby 总开关并成功保存后，本端预加载不再接纳候选，并撤销待执行和在途作业。重新开启只允许新的请求准备播放链接，关闭前的迟到响应不能恢复旧作业；飞牛预加载不受影响。Emby 代理启用仍要求本端启用并填写地址与 API Key。

Jellyfin 支持本地索引、静态多版本／分段、刷新、官方插件通知、主动提取和具有真实历史证据的联动删除。页面和播放使用 Jellyfin 自身地址，不提供 302、视频／字幕或页面代理。两端路径不同仍按下节映射规则；插件配置见 [Jellyfin 设置](../../wiki/Jellyfin-设置.md)，接口、产品识别与删除边界见 [媒体库同步](../architecture/emby-library-sync.md)。

## Emby 外部 STRM 路径映射

QMediaSync 在本端 Emby 或 Jellyfin 条目同步时自动确认 STRM 的路径对应。下列历史 `emby_root` 字段名也用于 Jellyfin，含义是该端媒体服务器的根。QMediaSync 生成和外部程序生成的 STRM 使用同一套路径规则：先确认文件来源，再按完整路径组件核对相对位置，允许两端的挂载前缀不同。单个条目即可保存自身的对应关系，无需先收集多个样本。

已有可靠文件关联时，使用记录中的本地路径和同步根计算对应；无文件关联时，只在同来源、同账号的已知 STRM 同步根下尝试有限的候选相对路径，读取候选 STRM 并核对播放来源。不会递归扫描磁盘、访问播放 URL 或调用网盘接口。没有可访问的候选文件、来源不符或存在无法排除的冲突时，保留未确认状态，不能把网盘视频路径当作 STRM 挂载位置。

“系统设置 → 媒体库 → Emby／Jellyfin”暂不显示手工 STRM 映射。已有手工配置继续生效并优先于自动推导；普通设置保存保留这些配置。自动结果保存在条目快照中，不写入手工配置数组。

两端配置使用各自 `GET/POST /api/setting/{emby|jellyfin}-config`，API 字段为 `path_mappings` 数组，分别保存为本端配置表的 `path_mappings_json`。每项包含：

| 字段 | 用途 |
| --- | --- |
| `emby_root` | 本端媒体服务器实际看到的 STRM 根目录，支持 POSIX、Windows 盘符和 UNC 绝对路径 |
| `local_root` | 同一批 STRM 在 QMediaSync 所在机器／容器中的可访问根，必须符合本机绝对路径规则 |
| `sync_path_id` | 可选；显式声明本端媒体根与所选网盘同步根保持相对媒体目录结构，省略或 `0` 只做本地访问映射 |

保存接口省略或传 `null` 保留原映射，传 `[]` 清空。根路径不能包含 `.`、`..` 或控制字符，Emby 根不能重复或互相覆盖；不能用普通字符串前缀匹配跨目录。选择同步目录时校验目录存在、来源受支持、对应账号存在、账号来源与同步目录来源一致且主体可确认；账号与远端根从现有同步目录取得，不另行配置。

例如已知本地同步根为 `/strm/电影`，文件记录为 `/strm/电影/示例电影/示例电影.strm`，Emby 使用 `/media/电影/示例电影/示例电影.strm`，程序可由共同相对路径 `示例电影/示例电影.strm` 得出 `/media/电影 → /strm/电影`。外部 STRM 在已知根中被唯一定位并核对来源后，同样可以自动确认。通过兼容接口提供手工映射时，填写两端目录前缀；`sync_path_id` 只在相对媒体目录结构确实与所选同步根一致时提供。

自动定位使用的本地根与网盘目录归属分别记录。找到实际 STRM 只解决文件访问位置，不能据此给未绑定来源增加整目录删除能力；播放 URL 替换规则也不能替代文件系统路径对应。

调整挂载、同步目录或手工映射后，应重新执行本端条目同步，保存新的对应关系。旧通知继续核对原快照中的路径、根和账号，不会按后来发现的路径补删。原 STRM 仍在或挂载根不可访问时保留网盘目标。行为与删除边界见 [Emby 外部来源](../architecture/emby-library-sync.md#外部-strm-来源和路径映射)。

## Emby 302 下载与本地媒体

下载策略取自编译嵌入的 `backend/assets/emby302.yaml`，修改后需要重新构建，没有对应的运行时开关。

| `emby.download-strategy` | 行为 |
| --- | --- |
| `direct`，或留空／省略 | 检查当前请求的 Emby 下载权限后，远程 STRM 返回直链跳转，本地或代理资源回源下载 |
| `origin` | 原下载请求交给 Emby 处理 |
| `403` | 禁用普通下载和同步下载接口，返回 HTTP 403 |

内嵌模板默认使用 `direct`。权限、同步下载及缓存边界见[Emby 代理下载权限](../architecture/authentication-sessions.md#emby-代理下载权限)。

内嵌模板的 `emby.local-media-root` 为 `/`，启动时不再覆盖。代理直接识别 Linux 绝对路径、Windows 盘符、网络共享及 SMB；该字段仅补充本地路径前缀识别，不是容器挂载或 STRM 路径映射。播放与 STRM 解析规则见[115 STRM 直链解析](../architecture/upload-and-strm-processing.md#115-strm-直链解析)。

## Emby 302 缓存

内置缓存开关取自编译嵌入的 `backend/assets/emby302.yaml`，`cache.enable` 默认 `false`；修改该模板需重新构建。它独立于主配置 `config.yaml` 中的 `emby302.insecure_skip_verify`，当前没有对应的运行时开关。

开启缓存后，通用响应使用 `cache.expired`，直链响应最多缓存 10 分钟。115 直链还受签名提前 5 分钟的安全期限约束，期限无法确认或取链失败时不缓存；命中不会延长期限。UA 隔离、失败回退和到期边界见 [115 STRM 直链解析](../architecture/upload-and-strm-processing.md#115-strm-直链解析)。

随机列表 `/Users/{id}/Items/with_limit?SortBy=Random` 的响应缓存 3 小时，并供后续随机重排复用。首次回源保持流式转发；读取上游响应体或向客户端写入失败时，部分内容不会进入响应缓存或 `UserItems` 缓存空间，也不会在已开始的响应后再次回源拼接内容。后续请求可重新回源，成功传输的完整响应仍按原有策略缓存。

## Emby 302 回源连接

通用 HTTP 回源转发（`ProxyRequest` / `ProxyPass`）随客户端取消中止请求，包括后续重定向和响应体读取，减少关闭播放或离开页面后的无效传输。独立 API 查询、后台加载和直链解析仍保留各自原有的请求生命周期。

Emby 302 自带的 OpenList JSON API 单次请求总上限为 30 秒，覆盖重定向和响应体读取；调用方取消或设置更短的截止时间时提前结束。该上限是固定内部策略，只约束单次 API 请求，串行查找多个根目录可能累计等待更久；视频流和下载不受此上限限制。QMediaSync 主业务的 OpenList 客户端独立管理超时。

Emby 通用回源仅在请求错误与客户端上下文均为主动取消时记录 `DEBUG`“客户端已取消 Emby 请求：接口=…”；仅保留请求路径，不输出查询参数或“代理请求失败”的错误包装。超时、网络错误和其他响应读写失败仍记录 `ERROR`“代理异常”。错误包装保留原始错误链，避免把正常取消误记为故障。

通用回源转发取消、读取上游响应体失败或向客户端写入失败时，不缓存已收到的部分响应；字幕的 30 天缓存同样遵守此条件。后续相同请求会重新回源，完整响应仍按原有策略缓存。

Emby 客户端访问内置 `socket` / `embywebsocket` 入口时，WebSocket 直接连接配置的 Emby 地址，不使用 `HTTP_PROXY` / `HTTPS_PROXY` 等系统代理环境变量。此行为无需开关，避免内网 Emby 的长连接被系统代理接管。

## Emby 302 出站 HTTPS

出站证书信任默认使用系统根证书。Windows 上若进程环境中的 `SSL_CERT_FILE` 或 `SSL_CERT_DIR` 非空，Go 1.27 会改用指定的磁盘证书来源，路径无效不会回退 Windows 证书库；不需要自定义信任库时应移除这些变量。升级后须在目标 Windows 环境验证 Emby、网盘及更新源的 HTTPS 连接。

Emby 302 代理访问 Emby、OpenList、m3u8 和下载资源时默认校验证书，并复用模块拥有的 HTTP 连接池。仅在受控内网自签名证书或临时排障场景下，才设置：

```yaml
emby302:
  insecure_skip_verify: true
```

启用 `emby302.insecure_skip_verify` 后，出站 HTTPS 请求会接受无法验证的证书，程序会写入风险提示日志。该模式存在中间人攻击风险，不适合公网或长期生产环境。

## Emby 302 图片与自定义脚本

主配置 `config/config.yaml` 的 `emby302.images_original` 默认 `false`，修改后重启生效。关闭时保留客户端请求的图片尺寸、格式等参数，仅按内嵌模板的 `images-quality` 覆盖质量；默认质量 `100` 不等于原图模式。

```yaml
emby302:
  images_original: true
```

开启后，海报、背景等图片请求会移除缩放、质量、格式、模糊、背景色及服务端播放标记叠加参数，不区分参数名大小写。裁剪和增强先清理所有大小写别名，再显式设置唯一的 `CropWhitespace=false`、`EnableImageEnhancers=false`，避免 Emby 的默认行为重新开启 Logo/Art 裁剪或图片增强。选图 `index`、版本 `tag`、认证及其他参数保留。这样可请求更清晰的原图，但图片流量、加载时间和客户端内存占用可能增加；Emby 服务端叠加的已播放标记、进度或未播放数量也不会再随图片生成。

配置目录 `custom-js/` 中的脚本在全局 `ApiClient` 存在且非 `null` 后执行；未就绪时每 100 毫秒检查一次，就绪后每个脚本执行一次。各脚本保留独立作用域，同步执行异常写入浏览器控制台，不阻断其他脚本。该条件不代表用户已登录或所有插件已加载。脚本和样式仍在首次访问时加载并缓存，修改文件后需重启服务。

## 出站代理

出站代理地址保存在 `settings.http_proxy`，支持 `http`、`https`、`socks5` 和 `socks5h`，可带 `用户名:密码@` 凭据。它由 Web 设置的「出站代理」保存，不读取环境变量。

保存代理时必须维护以下不变量：

- 刮削、代理与当前线程组由同一有限写入入口依序提交和发布。写入使用局部副本，数据库成功后再发布完整快照；GORM 回写待保存模型不能改变读者正在使用的配置。
- 新刮削、搜索和连接测试按各自入口捕获代理与有效参数，TMDB／Fanart 客户端不读取可变全局代理或密钥。清空代理或关闭 TMDB 代理后，新客户端使用不带该代理的连接池；旧任务保留已捕获配置。
- GitHub 访问管理器和稳定通知管理器的本地应用随同一次成功提交完成；通知代理重载保留命令登记并退役旧后台。Telegram 渠道仍使用原机器人时，重载或禁用后启用保留已处理的更新游标，回复尚未完成时也不会重新执行已处理命令；更换机器人采用独立游标。应用错误沿[网页设置的应用边界](#网页设置与应用边界)返回，不能掩盖为已经生效。

GitHub 连接探测结束后释放本次创建的私有连接池中的空闲连接；代理配置变更、显式清缓存或缓存过期重新探测时，也回收旧私有池的空闲连接。共享的默认连接池和正在进行的请求不受影响；重新探测失败时仍保留旧缓存客户端，供既有缓存回退接口使用。

`GET /setting/http-proxy` 一律回传脱敏地址，不回传明文凭据，任何 JWT 或 API Key 持有者都读不到代理密码。响应额外带 `credentials_masked`（`"1"` 表示地址里的凭据已被遮蔽），前端据此提示输入框里的 `xxxxx` 是占位串。

这带来一个必须成对维护的回环：前端把回传值直接载入输入框，并在尚未编辑脱敏值时自动提交 `preserve_proxy_credentials=true`；一旦用户编辑输入框则提交 `false`。保存和测试接口只有在提交地址与当前已存地址的端点一致时，才以该标志保留当前用户名和密码。端点由协议和 `host:port`（不区分大小写）组成，User 信息、路径和查询参数不参与比较；协议、主机或端口改变时忽略保留标志，绝不把已存凭据转发给新端点。因此 `xxxxx` 始终可以作为真实凭据保存，不再从最终字符串猜测用户意图。为兼容未升级的前端，缺少该字段时仍按旧的脱敏字符串回传规则处理；新的 API 调用方必须显式提交该字段。

代理地址写日志或回传接口前的脱敏要求见下一节。

Web 端代理请求由 `api/proxySettings.ts` 封装。保存成功后仍读取脱敏配置更新表单；回读失败单独显示加载失败，不显示包含刚输入凭据的成功说明。请求在 QMediaSync 来源或 CSRF 校验阶段被拒绝时，提示访问配置或安全校验原因，不误报为出站代理连接失败。

## 刮削服务配置

TMDB 与 Fanart 网页字段一次提交；运行时仅发布已提交的完整配置。每次刮削任务、搜索和连接测试各自捕获有效配置并拥有独立客户端，任务内复用，结束后释放私有连接池。语言、图片地址、API 地址、密钥和关联代理来自同一快照；TMDB 服务配额由各客户端共用，不因创建新任务重置。

AI 的 `ai_timeout` 控制单次请求的总等待预算，默认 120 秒；底层响应头等待不会提前缩短该预算。目录中的提示词用于本次 AI 识别请求。连接测试使用当前草稿及其超时，不发布草稿或改变业务客户端；旧请求省略超时时使用原默认值。AI 使用原默认 HTTP 环境代理规则，不接入网页出站代理或 TMDB 代理开关。

AI 连接测试遇到可识别的上游等待超时时返回 HTTP `504`，其他测试失败沿用原分类。OpenAI 兼容客户端从标准嵌套 `error.message` 保留供应商原因；无有效消息时保留 HTTP 状态，不直接打印完整错误正文。关联诊断仍通过当前草稿的 API Key 脱敏，响应使用安全提示；具体错误码见 [公共响应契约](../reference/api-response.md#http-状态与错误分类)。

密钥为空时仍按[第三方密钥优先级](#第三方密钥与本机敏感数据)回退。已有文件的后续处理边界见[网页设置与应用边界](#网页设置与应用边界)。

## 日志行为与脱敏

日志路径由 `config/config.yaml` 的 `log` 配置决定，默认相对于配置目录：

| 配置项 | 默认值 | 用途 |
| --- | --- | --- |
| `log.level` | `info` | 可选 `debug`、`info`、`warn`、`error` |
| `log.maxSizeMB` | `10` | 单个轮转日志最大大小，单位 MB，范围 1 到 1024 |
| `log.maxBackups` | `3` | 每个日志的轮转备份数，范围 1 到 100 |
| `log.maxAgeDays` | `7` | 轮转备份最长保留天数，范围 1 到 365 |
| `log.app` | `logs/app.log` | 主程序日志 |
| `log.v115` | `logs/115.log` | 115 请求和队列日志 |
| `log.openList` | `logs/openList.log` | OpenList 日志 |
| `log.tmdb` | `logs/tmdb.log` | TMDB 日志 |
| `log.baiduPan` | `logs/baidupan.log` | 百度网盘日志 |
| `log.web` | `logs/web.log` | 预留 Web 日志配置 |
| `log.syncLogDir` | `logs/sync` | 同步任务独立日志目录 |

历史 `log.file` 仍可读取；当 `log.app` 为空且 `log.file` 有值时使用旧路径，新保存统一写 `log.app`。全局日志按写入触发轮转并压缩旧文件；同步任务日志不轮转，随同步记录清理删除。Windows 的任务日志句柄允许文件在后台写入结束前被删除，保留追加写入和统一关闭的生命周期。`QLogger` 在写入前脱敏 `api_key`、Token、Cookie、密码、STS 密钥等常见敏感字段，脱敏值统一显示为 `******`。

未传入显式秘密值且正文不含敏感字段候选词时，脱敏先通过字符串预筛原样返回；其余情况继续执行原有脱敏规则。预筛保持大小写匹配和输出语义，显式秘密值的无字段名回显仍受保护。

普通 115／OpenList SDK 请求在 `INFO` 保留方法、接口、账号及已知 HTTP／业务状态；逻辑请求最终失败时记录一次含具体脱敏原因的 `ERROR` 摘要，错误类型只作补充。OpenList 接口定位包含实际来源和配置中的路径前缀。重试恢复成功不记最终失败，取消使用 `DEBUG`。未收到响应时 HTTP 为 `0`；业务字段缺失、为 `null`、未读取或无法解析时显示 `unknown`，实际解析到的零码仍显示 `0`。播放、预加载和删除核验继续使用各自的诊断规则。

开启 `DEBUG` 后，普通 SDK 成功和失败请求均可查看参数、适用的请求体及解析前已取得的原响应。正文在执行边界各记录一次，保留未知字段、数值、空值和业务文字；JSON 表示与原始字节、表单、multipart 参数分别标明，不读取上传文件内容或消费发送流。明确 HTTP 拒绝等原分支没有读取正文时说明“未读取”，读取失败时说明已有正文不完整。`SensitiveDebugText` 在原文本上先脱敏，再引用为单行日志，不默认截断为 4K／16K；脱敏只改日志副本，原请求、返回数据、错误链和重试语义保持。

默认正文保护密码、账号／会话 Token、Cookie、API Key、STS secret 和 URL 认证 userinfo；`token`、兼容字段 `AccessKeySecrett` 同样遮蔽，空字符串、`null` 和缺失字段保持原状。实际请求使用的旧／新 Token 和 STS 凭据随局部诊断上下文传递，覆盖无键名以及 HTML／非 HTML 的标准 JSON 转义回显。有效 JSON 的显式秘密替换按完整转义单元匹配编码后的凭据，仅作用于字符串值，不用裸值切开反斜杠或 Unicode 转义；保留键、数字、布尔、`null`、重复字段及非秘密部分的原表示，不重新解包编码。普通文本仍保护已知凭据的裸回显；显式秘密值不足 6 个 Unicode 字符时只按明确凭据字段遮蔽。用户名、路径、文件名、账号／任务／文件 ID、ETag 和校验值保留。普通 `INFO`／`ERROR` 原因始终脱敏，错误中任意 HTTP(S) URL 仍折叠为来源，详细接口参数在所属 SDK 的 `DEBUG` 查看。

普通 SDK 的 `DEBUG` 明确保留文件签名直链及文件访问签名参数，例如 115 CDN 地址的 `t/u/c/f`、OpenList 的 `raw_url/sign`，无需开启 unsafe；账号凭据仍遮蔽。这一规则不扩大普通 `INFO`／`ERROR`、播放或预加载的完整地址输出范围。日志读者在链接有效且访问条件满足时可能访问文件，分享日志前应检查相关链接。

OSS multipart 的成功摘要保留已有 ETag、MD5／CRC64、请求及上传标识和分片进度，详细参数、返回及 callback 放在 `DEBUG`，不展开媒体字节。SDK 失败及后台的独立本地／下载／解析错误、任务最终结论保留具体安全原因；重复 SDK 错误的过程日志保留操作和任务／文件上下文。上传、刮削和同步的持久化失败字段保持原语义。

SDK 正文默认写入 `115.log`／`openList.log`，这两个 logger 不同时写控制台；`app.log` 和同步任务日志默认同时写控制台，fnOS 关闭 QLogger 控制台输出。等级全局共享，改为 `debug` 也会放行应用和同步任务已有的 DEBUG 日志。等级前缀由 QLogger 添加，业务格式字符串不再手写 `[INFO]`／`[ERROR]` 等前缀。

STRM 本地文件对比继续保留逐文件 DEBUG 和缓存结构体详情；“本地 STRM 已对应网盘文件，跳过处理”使用 DEBUG，默认 INFO 不逐条输出已匹配文件的跳过记录。异步事件总线不再逐次记录发布事件及订阅者数量，事件分发、无订阅者诊断和处理器错误日志保持原有行为。媒体库刷新请求的成功日志见 [媒体库刷新](../architecture/emby-library-sync.md#链路-a通知媒体服务器刷新)。

本地对比开始时，空目录删除关闭及缺项清理保护原因各说明一次。非空目录保留、因关闭元数据下载或配置为保留而跳过元数据的逐项明细使用 DEBUG，INFO 在相应收尾位置汇总本次实际观察到的数量；没有命中时不输出零条目汇总，中断时的数量也只代表已经处理的部分。逐文件的本地／网盘对照路径、ID、PickCode，文件类型／最低大小筛选以及排除规则命中仍保留 INFO；实际操作、阶段结果和失败诊断保持原有等级。

历史、实时和任务快照按完整行读取，正常记录不受原 64 KiB／1 MiB 单行限制；分页条数、方向和游标保持原契约，详见 [实时事件](../architecture/realtime-events.md#日志-tailer-与事件字段)。完整长行会增加读取内存与传输量。实际单次轮转写入仍受 `log.maxSizeMB` 限制，长度包含时间、等级、引用转义和换行；超限整条拒绝，或其他写入错误发生时，直接向 stderr 输出含文件、实际字节数、上限和原因的短告警，不附正文。该告警不受 QLogger 等级或控制台开关过滤，也不自动分片或改变业务结果。被拒绝的正文没有保存，下载不能补回；调整已有上限后重新复现。同步任务日志不使用轮转上限。

查询媒体库同步状态时，“获取 Emby／Jellyfin 同步状态，最后同步时间”按实际产品展示，使用 `DEBUG` 等级；需要观察轮询记录时设置 `log.level: debug`。品牌展示使用官方名称，内部类型值、API 路径和配置键保持原样。

联动删除准备日志在 `INFO` 说明正在核验待删除文件；复用已有来源记录、补齐文件信息及本轮详情／目录结果复用等过程放在 `DEBUG`。身份冲突、查询失败和保留原因继续使用原有结果日志，不因降低准备过程的级别隐藏实际未完成情况。

Emby／Jellyfin 媒体通知日志把名称放在前面，ItemId 放在括号内，例如 `记忆管理局 S01E04（ItemId ...）`；整季使用 `剧名 S01`。完成状态区分条目同步与删除处理，删除处理完成不等于每个云盘对象都已删除，实际结果见同一通知的逐文件或目录结果行。缺少剧名或季号时使用本次已保存的可靠资料补足，不为日志增加查询。

115 播放日志在首次取链、缓存失效后刷新、取得副本直链并成功发布时，向主程序日志集中写入一次原始取链接口地址与最终直链，同时标注从直链路径解码的文件名、账号、原始 PickCode、取链来源、实际模式和 UA。地址记录使用到达 115 接口的请求 URL；副本操作在身份核验完成后另记原始和副本 PickCode。缓存命中和内置 Emby 入口跳转只输出文件名、UA 及对应结果，避免各层重复长地址，不额外维护日志去重缓存。

115 缓存检查日志明确标注 HEAD；检查开始和关闭检查的信息为 `DEBUG`，检查结果为 `INFO`。内置 Emby 跳转日志记录取链接口状态、发给播放器的跳转状态和目标域名；未取得响应时接口状态为 `0`。取链和 HEAD 请求失败日志会移除错误中回显的 URL，损坏的 `Location` 只记录解析失败，保留普通超时和连接错误。这些结果只表示取链、检查或跳转环节成功，不代表实际播放成功。直链解析边界见 [115 STRM 直链解析](../architecture/upload-and-strm-processing.md#115-strm-直链解析)。

正式播放采用 Emby 第三方直链缓存、Emby 外层媒体流跳转缓存或飞牛第三方直链缓存时，记录一条 `INFO`“播放请求命中缓存”，包含入口、缓存类型、已有地址可提取的文件名和本次有效 UA。飞牛原生请求在响应确实完成改写后记录，同一次响应有多个播放质量时只记录一次；取消、停止、未改写及下载等非媒体流响应不记为播放缓存命中。日志不新增查询、不回显完整签名地址，也不区分缓存来自预加载、上次播放还是并发取链。115／百度既有缓存命中文案保持原样，后台发现已有缓存仍按下面的 `DEBUG` 规则处理。

STRM 预加载沿用主程序日志和全局等级：`INFO` 仅在设置保存成功且开关实际变化时记录“STRM 预加载已开启”或“STRM 预加载已关闭”；实际取链并写入缓存成功时使用“预加载完成”，说明入口、触发场景、最终目标、网盘或第三方来源和后台执行耗时，不附任务编号、账号编号或尝试次数。触发场景区分电影详情、单集详情、剧集／季页待播集、播放接近结束及下一分段。目标优先使用已有资料中的名称和季集编号，缺失时显示条目编号；缺少名称不影响预加载，后台执行耗时不包含防抖和排队。单集资料齐全时，详情与列表预加载统一显示为“剧名 S01E01”，缺少有效季集号时保留单集名。复用现有缓存不记为新取链成功。缓存不可用、实际写入失败，以及已过期或剩余可缓存时间不足一秒的链接都不输出“预加载完成”；分别说明内存缓存不可用、剩余缓存期限不足一秒或未能写入缓存，不能误报为取消或地址格式错误。

`DEBUG` 说明候选替换、缓存复用、具体跳过／等待／撤销原因及一次受限重试，按需附任务编号和已知账号、尝试次数。原因使用直接说明结果的文案，区分“没有查到待播单集”“无法确认待播单集属于当前剧集或季”“未能从媒体服务器获取资料”和播放地址缺失；不能将查询失败写成“没有下一集”，也不重复输出一条无原因的“已跳过”。受限重试说明等待时间和下次触发条件，不暗示到点自动重试。`WARN` 记录网盘受限、授权失效及最终取链失败，说明冷却或播放时的正常回退；首次可重试失败使用 `DEBUG`。`ERROR` 只用于后台自身无法继续工作的异常。HTTP 状态和业务码仅在已知且有诊断意义时显示，注明来自媒体服务器还是网盘，不输出未知零值，也不补造成功状态码。预加载失败不等于播放失败，实际点击播放仍按普通流程处理。默认等级不逐详情或心跳输出，同候选同原因不反复记录，账号冷却只在进入时警告。

后台取链跳过普通播放的完整地址／原始响应日志。目标名称只复用现有响应或本轮原有补查结果，经控制字符清理、限长和引用后输出；不为了日志补 SQL、网络或文件读取。所有等级均不输出凭据、完整 STRM／签名 URL、原生正文或未经处理的外部错误。日志格式化和写入位于队列、配置、槽位和后台同键锁之外，继续复用现有有界状态。上述普通播放日志的既有输出规则不因预加载而改变。

同步任务遍历本地文件时，正常的文件存在性对比和“无需处理”的原因使用 `DEBUG` 级别；实际删除本地 STRM、上传或重新下载元数据等动作使用 `INFO` 级别。对比命中远端文件时，`DEBUG` 日志会以带字段名的完整 `SyncFileCache` 结构输出，便于排查文件 ID、路径、大小、时间和来源等信息；未命中时只输出本地路径和不存在结论。普通 `QLogger` 格式化日志的脱敏基于键值对匹配；SDK 正文入口另外遮蔽 HTTP(S) URL userinfo。凡是可能带凭据的代理 URL，仍须在调用点用 `validation.RedactProxyURL`（入参为原始字符串）或 `validation.RedactParsedProxyURL`（入参为已解析的 `*url.URL`）处理后再写日志或回传接口，保留 opaque 等代理地址的既有契约。

不要使用标准库的 `url.URL.Redacted()`：它只替换密码，用户名仍是明文（企业代理常带域账号，形如 `http://DOMAIN\jsmith:pw@proxy.corp:8080`）；并且它对缺少 `//` 的 opaque 地址（形如 `socks5:user:secret@host:1080`）完全不生效，会把密码原样输出。上面两个函数同时遮蔽用户名和密码，覆盖 opaque 地址，并在 `url.Parse` 失败时返回占位符而不是原串。

`url.Parse` 失败时也不能直接外抛 `url.Error`，它的 `Error()` 会渲染成 `parse "<整个原始地址>"`，等于把凭据原样写进日志或接口响应，统一用 `validation.ProxyParseError` 剥掉原串。

这三个函数放在 `internal/validation`（纯 stdlib 叶子包）而不是 `helpers`：`helpers/net.go` 已导入 `internal/github`，`github` 无法反向引用 `helpers`。需要脱敏代理地址的包一律引用 `validation`，不得再复制一份实现。

`GET /setting/notification/channels/telegram/{id}` 回传的 `config.proxy_url` 同样脱敏：该字段由历史迁移从 `settings.http_proxy` 复制而来，可能带凭据。凡是把含 `proxy_url` 的配置结构体整体写进响应的接口都要先脱敏。

`QMS_UNSAFE_SENSITIVE_LOG=1` 仅让敏感 DEBUG 输出跳过脱敏，不是查看完整正文的前提，也不解除普通 INFO／ERROR 的掩码或播放／预加载排除。它可能写出 API Key、Token、Cookie 或密码，只供本地临时调试，相关日志不可分享。`backend/assets/emby302.yaml` 默认关闭 ANSI 颜色，避免控制字符进入日志。

管理员恢复结果写入现有应用日志，成功记录不受日志等级过滤；新密码始终直接交付给终端或 Windows 系统窗口，不进入应用日志。Compose 恢复脚本还会关闭临时容器的 Docker 日志驱动。完整凭据交付契约见 [认证会话](../architecture/authentication-sessions.md#本地管理员恢复)。

## 第三方密钥与本机敏感数据

- 115 开放平台 APP ID、TMDB API Key / Access Token、OpenAI 兼容 API Key 和 fanart.tv API Key 可以在 Web 设置中配置。
- 默认密钥也可由 `backend/main.go` 的变量、ldflags 或环境变量 / `config/.env` 注入。`FANART_API_KEY`、`TMDB_API_KEY`、`TMDB_ACCESS_TOKEN` 和 `SC_API_KEY` 的优先级是 Web UI > 环境变量 / `config/.env` > ldflags；`config/.env` 覆盖真实环境变量。
- `.env` 实际从 `helpers.RootDir/config/.env` 读取，不随 `helpers.ConfigDir` 改变。Docker 和普通发布包中两者通常对应同一配置位置；飞牛共享配置目录可能与程序根目录不同，不能假定共享目录中的 `.env` 会被加载。飞牛优先通过网页设置可配置的第三方密钥。
- `SC_API_KEY` 用于 AI 识别默认密钥回退，不是 Server酱通知密钥；Server酱的 `SCKEY` 在通知渠道中配置。
- 两步验证等本机敏感数据使用首次启动自动生成的 `config/encryption.key`。`jwtSecret` 为空或仍为公开默认值时会生成 32 字节随机密钥并写回配置；修改它会使现有登录 Cookie 失效。
- 数据库 ZIP 不包含配置文件或 `encryption.key`。迁移须保留整个原 `config/`，在启动前安装原密钥；备份恢复不重新加密 TOTP，缺失原密钥不能由数据库备份补回。迁移和重启步骤见[数据库运维](database.md#备份)。
- OAuth 中转使用 `OAUTH_RELAY_ENCRYPTION_KEY`，可由 `main.OAuthRelayEncryptionKey` ldflags 或环境变量 / `config/.env` 注入，环境变量优先。

浏览器 Cookie、CSRF、初始化管理员、API Key 和可信来源等安全契约见 [认证会话](../architecture/authentication-sessions.md)。
