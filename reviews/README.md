# 审查记录

本目录保存针对某次具体改动的审查记录：需求梳理、技术设计、执行计划和分领域审查报告。

这些内容**不是正式文档**，不进入 [文档索引](../docs/README.md)。按 [文档治理](../docs/engineering/documentation-governance.md) 的职责边界，"仅服务某次改动的设计草案、执行计划和排查过程"不写入 `docs/`，应留在 Git 历史中；本目录就是这些记录在版本库中的落点。

## 使用约定

- 每次审查一个子目录，命名为 `<MM-DD>-<主题>`，例如 `07-29-backup-refactor`。
- 记录反映**写入时**的代码状态和当时未修复的问题，不随后续改动更新；要查当前行为请读 `docs/` 下的权威文档和源码。
- 不要把这里的结论当作契约。发现某条结论具有长期价值时，把它迁移到对应的权威文档，而不是让维护者回来读审查记录。
