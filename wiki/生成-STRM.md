# 生成 STRM

STRM 是保存播放地址的小文件。QMediaSync 会为视频生成对应的 `.strm`，按设置下载 NFO、海报、字幕等元数据，供 Emby 读取；生成 STRM 本身不会把整部视频下载到本地。

首次使用建议先选一个只有几部影片的小目录，确认路径、元数据和播放都正常后，再添加其余目录。电影和电视剧分开添加，后续刮削、媒体库分类和排查会更清楚。

## 先准备账号和目录

115 网盘、百度网盘和 OpenList 需要先在「网盘账号」中添加对应账号，操作见 [账号管理](账号管理.md)。本地目录不需要添加网盘账号，但 QMediaSync 必须能读取该目录。

Docker 中的“本地目录”是**容器内的路径**。例如宿主机 `/volume1/media` 挂载到 QMediaSync 容器的 `/media`，页面里应选择 `/media`。Emby 也需要挂载生成的 STRM 所在目录，具体见 [Docker 安装](Docker安装.md) 和 [文件权限相关问题](文件权限相关问题.md)。

## 设置 STRM 和元数据

进入「STRM 同步 → STRM 设置」，检查以下内容后保存。

| 设置 | 怎么选 |
| --- | --- |
| STRM 直连地址 | 填写可以稳定访问 QMediaSync 的地址，例如 `http://192.168.1.2:12333`。至少要让 Emby 能访问；不要使用可能变化的容器 IP。外网播放还需要核对播放器实际访问的地址，见 [Emby 外网 302](Emby外网302.md) |
| 视频文件扩展名 | 确认包含自己的视频格式。需要处理 ISO 时检查是否已添加 `.iso` |
| 最小文件大小 (MB) | 小于阈值的视频会跳过。默认 100 MB 可能过滤短剧、短片或小体积剧集，可按资源实际大小调整 |
| 排除名称、正则排除名称 | 命中的文件或目录会跳过；排除了父目录，其中的视频也可能不生成 STRM。普通规则按完整名称匹配并忽略大小写，正则按原始大小写匹配 |
| 元数据扩展名 | 检查需要保留的 NFO、图片和字幕格式，例如 `.nfo`、`.jpg`、`.srt`、`.ass` |
| 下载元数据 | 选「是」会补充本地缺少的元数据。选「否」还会跳过后续元数据处理：已有本地元数据保留，新增的也不会上传 |
| 网盘不存在的元数据 | 「删除」会删除本地有、网盘没有的元数据。「上传」会在网盘父目录仍存在时上传；如果父目录已在网盘删除，仍可能清理相应本地文件。不要把这一项当成无条件保留本地文件的开关 |
| 检查元数据修改时间 | 开启后会比较两端修改时间：远端较新时下载更新，本地较新且允许上传时上传更新。已有本地刮削结果时，先确认自己希望哪一端提供内容 |
| 网盘不存在的空目录 | 选「删除」会清理本地对应的空目录 |

“同步”会核对来源和本地结果，并可能清理已确认失效的本地 STRM 或元数据。请使用专门的 STRM 输出目录，不要把独立保存的重要文件混放进去。

## 添加同步目录

1. 进入「STRM 同步 → STRM 同步目录」，点击「添加同步目录」。
2. 选择同步源类型；网盘来源再选择已经授权的账号。
3. 在「来源路径」选择需要同步的网盘目录或本地目录。
4. 在「目标路径」选择 QMediaSync 用来存放 STRM 的本地位置。
5. 核对页面自动计算的「STRM 存放目录」，这里才是 STRM 和元数据的实际位置。
6. 没有单独需求时保持「自定义设置」关闭，使用全局 STRM 设置；然后点击「保存设置」。

例如：

| 项目 | 值 |
| --- | --- |
| 来源路径 | `/Media/电影` |
| 目标路径 | `/media` |
| 实际 STRM 存放目录 | `/media/Media/电影` |

Emby 添加媒体库时，需要选择它自己能看到的这份输出目录。若两个容器把同一个宿主机目录挂载成不同路径，Emby 中应选择 Emby 容器内的路径。

开启「自定义设置」后，可以为这个目录单独设置过滤和元数据规则。扩展名及排除列表非空时使用本目录的列表；清空相应列表并保存后恢复继承全局设置。「导入全局设置」会把全局项目合并进当前列表，不是建立持续跟随全局变化的关系。

## 首次同步、增量和全量

不同来源的同步方式不完全相同：

| 来源 | 首次操作 | 后续使用 |
| --- | --- | --- |
| 115 网盘 | 点击「全量同步」核对整个来源目录 | 日常可用「增量同步」。在其他工具中改名、移动目录后，如果本地仍是旧路径，执行一次全量同步重新核对 |
| 百度网盘 | 点击「全量同步」，或使用会自动执行当天首次全量的同步入口 | 服务器当天尚无成功完成的全量任务时，会先做全量；当天已有成功全量后才做增量。增量不能靠“没有出现某个文件”判断它已经删除 |
| OpenList、本地目录 | 点击「同步」 | 页面不提供与 115 相同的增量、全量按钮组合，按当前来源的扫描方式核对目录 |

全量同步会重新核对整个目录，不表示一定要重写每一个本地文件，也不应理解为“先把本地文件全部删掉”。它通常比日常同步耗时更长。

同一来源的同步和刮削工作可能需要排队。点完按钮后显示等待时，不需要反复点击。需要中止时点击目录卡片的「停止」，随后到同步记录确认最终状态；停止请求提交成功不代表所有工作已在同一瞬间结束。

## 定时执行

在同步目录卡片开启「定时同步」后，这个目录才会参与定时任务。

- 没有填写目录自定义表达式时，使用「STRM 设置」中的「定时同步表达式」。
- 想单独安排这个目录，编辑目录，开启「自定义设置」，填写「定时同步表达式」并保存。
- 有自定义表达式的目录使用自己的时间安排，不会再同时使用全局时间安排。

例如 `0 3 * * *` 表示每天凌晨 3 点，`0 */6 * * *` 表示每 6 小时。以页面显示的后续执行时间核对服务器时区。**定时触发不等于所有来源都执行增量同步**，仍遵循上一节的来源差异。

## 怎么确认同步完成

1. 打开「STRM 同步 → STRM 同步记录」，查看本次记录和详情。
2. 如果显示「部分完成」或「扫描不完整」，查看失败文件、目录和日志，先处理具体原因；已成功处理的部分可能已经可用。
3. 如果启用了元数据下载，再到「上传下载 → 下载队列」检查字幕、NFO、图片是否处理完。存在上传工作时也要查看「上传队列」。
4. 确认 Emby 能读取 STRM 目录，并扫描媒体库。无法播放时按 [Emby-无法播放问题的排查步骤](Emby-无法播放问题的排查步骤.md) 检查。

同步记录的生成阶段结束后，后台保存、元数据传输或 Emby 刷新仍可能继续。各状态的含义和队列操作见 [任务与通知](任务与通知.md)。

## 只为选中的文件或目录生成 STRM

偶尔补做几个文件时，可以使用「网盘文件管理」：

1. 选择网盘账号，找到需要处理的文件或目录。
2. 使用单项操作中的「STRM 生成」，或者勾选多个项目后点击「STRM 生成」。
3. 在弹窗选择本地目标目录，核对显示的存放路径后确认。
4. 等任务执行，并检查同步记录和实际生成文件。批量提交出现部分失败时，按提示核对失败项。

这个入口使用全局 STRM 设置，提交的是临时任务，不会保存成可定时执行的同步目录，也不会自动触发关联刮削或 Emby 刷新。需要长期保持目录更新时，仍应按前文添加同步目录。

## 同步后自动刮削本地 STRM

适用于先生成 STRM，再对本地 STRM 刮削的用法。

1. 按 [刮削指南](刮削指南.md) 创建一个来源类型为「本地目录」的刮削目录，来源路径选择实际生成 STRM 的目录，并确认视频扩展名中包含 `.strm`。
2. 回到「STRM 同步目录」，点击对应卡片的「关联」。
3. 选择需要触发的本地刮削目录，可以多选，确认保存。

本次同步实际生成或更新了 STRM 文件后，会把关联的本地刮削目录加入执行队列。没有 STRM 变化、只处理元数据时不会触发；入队后仍需等待正在执行的任务，不保证立即开始或固定等待多少秒。

## 网盘刮削后生成 STRM

适用于先在网盘完成刮削整理，再把结果写入本地 STRM 目录。

1. 先建立一个 STRM 同步目录，使用与刮削目录相同的来源和账号；其来源路径需要覆盖刮削后的网盘目标路径。
2. 在「刮削 & 整理 → 刮削目录」找到对应的**非本地**刮削目录，点击「关联」。
3. 选择匹配的 STRM 同步目录并保存，再执行刮削整理。

程序会根据本次整理结果生成 STRM 并复制元数据，不再为此启动一次完整目录同步，也不会新增一条完整同步记录。刮削整理本身仍可能访问网盘。

虽然可以关联多个目录，每部影片会使用与整理后路径匹配的第一个关联目录。多个关联适合覆盖不同路径范围，不能用它把同一影片同时分发到多个本地目标。

需要把本地新文件自动上传至 115 网盘，再生成 STRM，使用 [目录监控上传](目录监控上传.md)。

需要让外部程序在 115 文件到达后通知 QMediaSync 生成 STRM，见 [STRM Webhook](STRM-Webhook.md)。
