# 刮削指南

刮削是给视频匹配影视信息，生成 NFO、海报等文件；整理是把视频按规则移动、复制或链接到目标目录，并重新命名。可以只刮削，也可以把两步一起执行。

**电影和电视剧请分开添加刮削目录。** 每个目录只能选择一种媒体类型，不适合把混合目录一次当成同一类型处理。首次使用先放几部影片试运行，确认识别和目标路径正确后再扩大范围。

## 先分清路径和操作方式

网盘来源的「来源路径」和「目标路径」都是该账号内的网盘路径；本地来源的两条路径都是 QMediaSync 能看到的本地路径。Docker 部署时填写容器内路径，挂载和权限见 [Docker 安装](Docker安装.md)、[文件权限相关问题](文件权限相关问题.md)。网盘账号还没添加时，先看 [账号管理](账号管理.md)。

| 操作方式 | 会做什么 |
| --- | --- |
| 仅刮削 | 在原位置生成视频对应的 NFO、图片等元数据，不移动、不重命名视频，不需要目标路径 |
| 刮削和整理 | 获取影视信息、生成元数据，再按整理方式和命名模板放到目标路径 |
| 仅整理 | 使用已有或查询到的信息整理，不重新生成整套刮削元数据；「其他」类型必须先有 NFO |

需要整理时，再选择文件如何到达目标目录：

| 整理方式 | 适用场景和后果 |
| --- | --- |
| 移动 | 视频离开原位置，转到目标位置 |
| 复制 | 原视频保留，目标位置新增一份文件 |
| 软链接 | 仅限本地来源。目标视频链接到原文件，原文件删除或路径变化后链接可能失效 |
| 硬链接 | 仅限本地来源，并要求文件系统支持；通常需要源和目标在同一文件系统内 |

电影和电视剧的「仅整理」会处理视频及匹配字幕，不自动搬运原有图片和 NFO；「其他」类型还会处理匹配的图片和 NFO。已有完整元数据需要保留时，先用少量文件确认实际结果。

## 一个 115 网盘电影整理示例

假设希望把未整理的电影放到 `/待刮削/电影`，完成后放到 `/已刮削/电影`：

1. 在网盘中建立这两个目录，把几部待处理电影放进 `/待刮削/电影`。
2. 进入「刮削 & 整理 → 刮削目录」，点击「添加刮削目录」。
3. 来源类型选「115 网盘」，选择已授权账号；媒体类型选「电影」。
4. 操作方式选「刮削和整理」。本例整理方式选「移动」，意味着完成后视频不再保留在待刮削目录；需要保留原视频时选择「复制」。
5. 来源路径选 `/待刮削/电影`，目标路径选 `/已刮削/电影`。
6. 根据需要开启二级分类。开启后会在目标路径下增加分类目录，再放入影片目录。
7. 文件夹和文件重命名模板可以先用 `{title} ({year})`；完整变量及留空行为见 [整理文件（夹）模板可用变量](整理文件（夹）模板可用变量.md)。
8. 检查「最小视频文件大小」和「视频文件扩展名」，避免想处理的视频被过滤。刮削 STRM 时需要包含 `.strm`，并使大小阈值允许小文件。
9. 「启用 AI 识别」可以先选「辅助识别」；其余选项按下一节确认。首次试运行可以先关闭「定时任务」。
10. 保存后点击目录卡片的「扫描」，然后到「刮削记录」查看识别、刮削和整理结果。

电视剧另外建立 `/待刮削/电视剧` 和 `/已刮削/电视剧`，新增媒体类型为「电视剧」的刮削目录。文件夹可沿用 `{title} ({year})`，文件名可用 `{title} - {season_episode}`，例如 `示例剧集 - S01E01.mkv`。

## 需要特别确认的设置

### 删除整理完的非空路径

使用「移动」整理后，这个开关会改变原目录的清理方式；「仅刮削」、复制和链接方式不按这项规则清理源目录：

- 关闭：只清理整理后留下的空目录。
- 开启：可能直接删除视频原来所在的非空目录，里面残留的广告、文档或其他文件也会一起删除。

如果源目录还存放需要保留的文件，请保持关闭。它与 [目录监控上传](目录监控上传.md) 中的「上传后删除源文件」是两项独立设置。

### AI 识别

| 选项 | 用途 |
| --- | --- |
| 禁用 | 不使用 AI 识别，适合名称规范、常规识别已能成功的文件 |
| 辅助识别 | 其他方式无法识别时再使用 AI |
| 强制使用 | 始终使用 AI 识别，需要配置自己的 API Key |

自有 AI API Key、接口地址和模型在「刮削 & 整理 → AI 识别设置」中配置。使用什么模型以当前设置为准，不要照旧教程假定始终使用固定模型。AI 识别也可能出错，完成后仍需核对名称、年份和季集。

### fanart.tv

fanart.tv 用来补充图片。需要更丰富的图片时可以开启；更关注处理速度时，可以先关闭，在确认基础刮削正常后再决定是否启用。速度会受网络和服务响应影响。

## 定时任务怎么运行

刮削目录卡片和编辑页中的「定时任务」控制该目录是否自动执行：

- 开启且没有自定义 Cron 表达式时，参加默认每 13 分钟一次的刮削扫描。
- 开启且填写了自定义表达式时，按该目录自己的时间执行，不再参加默认的 13 分钟扫描。
- 关闭时，可以随时点击「扫描」手动运行。

Cron 使用「分 时 日 月 周」五段格式，例如 `0 3 * * *` 表示每天凌晨 3 点。保存前核对页面中的说明和服务器时间。

刮削后的整理会衔接执行，没有独立的“每隔一段时间整理一次”设置，也没有旧教程中的「触发一次整理」按钮。任务正在运行或等待时，可以在目录卡片点击「停止」，随后检查记录的实际状态。

## 本地刮削怎样调整速度

「刮削线程数」在**每个刮削目录的编辑页**，不是全局「刮削设置」中的独立线程选项。默认值为 5；本地目录只有配置了自己的 TMDB API Key 后，才可以使用高于默认值的并发数。网盘来源不靠调高这个值提速。

可以按以下顺序调整：

1. 先确认 QMediaSync 能正常访问 TMDB，并在「刮削设置」填写自己的 TMDB API Key。
2. 编辑本地刮削目录，适当增加「刮削线程数」，观察错误和机器负载后再继续调整。
3. 对命名规范的文件先禁用 AI 识别，按需要关闭 fanart.tv，手动扫描少量文件比较耗时。
4. 如果只有部分文件识别失败，为这些文件恢复 AI 辅助识别，再按下一节处理失败记录。

CloudDrive 等工具挂载的网盘虽然显示为“本地目录”，读取时仍会访问远端。不要按本地硬盘的速度预期盲目增加并发。

## 识别错了或失败了怎么处理

进入「刮削 & 整理 → 刮削记录」，先区分是哪一步出错。

| 情况 | 操作 |
| --- | --- |
| 识别成另一部作品、年份或季集不对 | 使用记录中的「重新识别」，填写正确名称、年份或 TMDB ID，并核对电视剧季集信息 |
| 刮削失败 | 先看记录和日志中的具体错误，检查 TMDB、AI 服务、网盘授权或本地权限。修正后，可删除对应失败记录，再回到目录点击「扫描」 |
| 整理失败 | 先确认目标目录权限、空间、文件冲突及网盘授权，选择失败记录后点击「重新整理所选」，它们会标记为待整理，在下次任务执行时重试 |
| 需要重新处理一批失败项目 | 「清除失败记录」会清除失败的刮削记录；来源中仍存在的视频可在下次扫描时重新进入处理 |
| 需要反馈识别问题 | 选择相关记录，点击「导出识别错误」，检查导出内容后再随问题反馈提供 |

删除刮削记录不等于删除视频。只要视频还留在被扫描的来源目录，下次扫描就可能再次识别和刮削。不要为了让列表好看而反复清空全部记录。

“回滚”会把已进入回滚流程的视频和字幕放回原目录，并在成功后移除对应记录。程序每 2 分钟处理一次这类回滚记录；这不是对所有刮削失败、整理失败项目自动重试。

## 整理“其他”类型

「其他」适合已经有 NFO、只需要按其中的信息整理的文件。它不能刮削，也不查询 TMDB。

在视频旁准备匹配的 NFO，再选择「其他 → 仅整理」。支持的 NFO 包括对应视频名的 `.nfo`、`movie.nfo`、`tvshow.nfo`、`season.nfo` 等；没有可用 NFO 的视频会跳过。变量取值和缺少信息时的处理见 [整理文件（夹）模板可用变量](整理文件（夹）模板可用变量.md)。

## 与 STRM 同步衔接

有两种常见用法，配置方向不同：

- **先生成 STRM，再刮削本地 STRM**：在 STRM 同步目录卡片中关联本地刮削目录。
- **先刮削整理网盘视频，再生成 STRM**：在非本地刮削目录卡片中关联同来源、同账号且覆盖整理后目标路径的 STRM 同步目录。

具体步骤和多个关联目录的范围见 [生成 STRM](生成-STRM.md)。网盘刮削后的 STRM 写入使用本次整理结果，不创建一条完整 STRM 同步记录；刮削本身的结果仍在刮削记录中查看。
