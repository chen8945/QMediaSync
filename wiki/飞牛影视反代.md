# 飞牛影视

如果你已经用飞牛影视管理 STRM，想继续使用 QMediaSync 的取链和播放设置，可以开启「飞牛影视反代」，通过新的入口打开飞牛影视网页，或连接兼容播放器。

**功能默认关闭。不使用飞牛影视的用户无需配置，原来的 Emby、同步、刮削和播放方式照常使用。** 此功能不替你安装飞牛影视、生成 STRM 或扫描媒体库。

当前支持飞牛影视的 Emby 兼容 STRM 播放，以及飞牛影视 0.9.8 的自带网页 STRM 直接播放。其他版本、手机和电视客户端请实际播放确认，不能仅凭能登录就判断播放已生效。

飞牛账号被禁用、禁止播放或设置了强制远程来源转码时，反代会交回飞牛处理，不强行开启直播放；禁止下载时也不会通过下载入口绕过限制。播放器明确请求转码时，也保留飞牛返回的转码方式。飞牛影视 0.9.8 的部分客户端请求方式可能收到网页而非播放信息，反代会保留飞牛的原响应；遇到这类情况，应核对客户端连接方式和版本，不把它当作路径映射问题反复修改。

## 开启前准备

- 飞牛影视已经运行，并能用原来的账号正常登录和播放。
- QMediaSync 能连接飞牛影视，且能读取同一批 STRM 文件。
- Docker 用户先挂载 STRM 文件夹；fnOS 原生应用先给 QMediaSync 授权该文件夹。路径和权限问题见 [文件权限相关问题](文件权限相关问题.md)。

不需要把飞牛影视账号密码保存在 QMediaSync 设置中，播放器仍使用自己的飞牛影视账号。

## 在网页中配置

1. 打开 QMediaSync 的「系统设置 → 飞牛影视」。
2. 开启「启用反代」。
3. 填写「飞牛影视地址」，例如 `http://192.168.1.20:8005`。这里填**原飞牛影视服务的根地址**，不要填 QMediaSync、新反代入口、网页中的具体页面或 `/emby` 路径。
4. 路径相同可以先不添加映射；两端路径不同时，按下一节填写对应文件夹。
5. 点击保存，程序会立即应用飞牛设置，**无需重启 QMediaSync**。
6. 查看页面上方的运行状态和保存按钮附近的结果。如果提示“已保存但未应用”，按错误说明处理后再次保存，不要把“已保存”当成入口已经可用。

启停、修改飞牛地址或路径映射后保存，会中断通过该入口进行的播放和长连接，再按新设置运行；QMediaSync 主站和原 Emby 服务不会重启。同一份健康设置重复保存不会打断播放。保存失败时保留原运行状态；已保存但应用失败时不会自动退回旧配置，请修正原因后再次保存。

Docker 需映射容器端口 `9005`，例如在原 Compose 的 `ports` 中增加 `"19005:9005"`，播放器随后访问宿主机的 `19005`。保留原来的配置与挂载，按原方式更新容器。防火墙或路由器也需按实际范围放行；网页保存不会自动处理这些部署配置。

## 路径映射怎么填

映射用于告诉 QMediaSync：飞牛影视中的这个文件夹，对应 QMediaSync 能读取的哪个文件夹。

比如同一份 STRM 文件：

```text
飞牛影视看到： /vol1/media/strm/电影/示例电影.strm
QMediaSync 看到：/media/strm/电影/示例电影.strm
```

添加一条：

| 设置 | 示例 |
| --- | --- |
| 飞牛影视中的 STRM 文件夹 | `/vol1/media/strm` |
| QMediaSync 中的 STRM 文件夹 | `/media/strm` |

只需填写不同的文件夹前缀，后面的 `电影/示例电影.strm` 会保留，通常不需要每部影片添加一条。可以添加多组，但飞牛一侧不要重复或相互包含。

QMediaSync 一侧可以点击「选择文件夹」，也可以手动输入；飞牛一侧按它实际看到的路径填写。Docker 中填写的是 QMediaSync **容器内路径**。确认选择只修改当前表单，点击主页面保存才生效；取消选择保留原值。

两端路径相同、文件位于 QMediaSync 已知输出目录时，通常无需映射。路径不同且无法可靠确认对应关系时，需要手动填写；不要因为文件同名就假定它们对应。映射不会修改 STRM、播放地址或媒体库路径，也不会授予文件权限；还没挂载或授权时，先完成这些准备。

## 在播放器中连接

假设 QMediaSync 的局域网地址为 `192.168.1.10`，Docker 使用上面的 `"19005:9005"` 映射：

```text
http://192.168.1.10:19005
```

在浏览器打开这个入口，即可使用飞牛影视自带网页；也可以在支持飞牛影视 Emby 兼容协议的播放器中填写它。使用**原飞牛影视账号**登录。直接运行 QMediaSync 时使用端口 `9005`；Docker 使用实际映射的宿主机端口。不要把 QMediaSync 管理员账号填进播放器。

依次确认：能登录、能看到媒体库、STRM 可以播放、字幕正常、拖动进度可用，原来的本地视频也能正常播放。再用实际外网设备测试一次；只在服务器上访问成功不能证明外网播放器可用。

STRM 文件里写的是当前这台 QMediaSync 的内网播放地址时，反代会继续使用本实例的取链能力，播放器不必另行访问那个内网管理地址。不过，**外部 OpenList 地址、其他外部播放地址或最终网盘视频地址仍须对播放器可达**；开启反代不能自动代理所有外部私有链接。

## 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| 保存后入口打不开 | 查看实际错误；排除 `9005` 占用后再次保存，并检查 Docker 发布和防火墙；普通保存无需重启 |
| 地址填好却反复跳转或打不开 | 是否把原飞牛影视地址填成了反代自身、QMediaSync 或 Emby 端口 |
| 能登录、看见媒体但 STRM 不生效 | 确认打开的是反代入口，检查飞牛版本、客户端连接方式、账号播放设置、两端同一 STRM 路径及挂载权限；未支持的播放方式仍交回飞牛处理 |
| 能播放但下载未被接管 | 检查飞牛账号的下载权限；播放权限不代表允许下载 |
| 暂停、退出正常，但重新打开仍从头播放 | 检查飞牛是否正确识别影片时长。测试样本在飞牛中的时长为 0，网页会把已保存进度也按 0 处理；仅临时修正时长就能继续播放。需处理飞牛的时长识别，反复修改路径映射无法解决 |
| 文件同名但没有自动匹配 | 同名不能证明是同一份文件；按实际挂载填写根目录映射 |
| 取得地址却不能播放 | 从播放器所在网络检查外部地址或最终视频地址，核对原来的网盘授权及播放代理设置 |
| 修改 STRM 后仍有旧结果 | 先核对改的是两端使用的同一文件；必要时关闭并保存，再启用并保存以清理本模块缓存，这会中断本模块播放。旧链接仍需更新文件，缓存不会生成新链接 |
| 换机器或恢复后不能用 | 恢复后重启，再核对端口映射、挂载和路径映射；若与 QMediaSync 或 Emby 端口冲突，飞牛入口会停止并显示原因，管理页面继续可用；不含飞牛配置的旧备份恢复后默认关闭 |

飞牛配置随数据库备份，STRM 文件需另行保留，操作见 [备份与恢复](备份与恢复.md)。错误沿用现有日志页面和程序日志查看，不需要配置额外目录监控、实时推送或专用日志页。

数据库恢复后仍须按恢复结果重启 QMediaSync，普通设置保存不能解除恢复维护；此步骤与日常保存立即生效不同。

反馈时提供 QMediaSync 与飞牛影视版本、客户端、错误时间和部署方式；遮住密码、Token、Cookie、私钥及带签名的播放链接。
