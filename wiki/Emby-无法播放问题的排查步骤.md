# Emby 无法播放问题的排查步骤

先选定**同一部影片、同一个播放器、同一个网络**，分别通过原 Emby 入口和 QMediaSync 的 Emby 代理入口测试。这样才能判断问题出在文件、Emby，还是代理和外网访问。

下面以原 Emby 使用 `8096`、QMediaSync 主服务使用 `12333`、Emby 代理使用 `8095` 为例。端口改过时，请使用自己的实际端口。

## 1. 先确认 Emby 能看到正确的文件

1. 在 Emby 中查看影片实际对应的文件，确认它是你要播放的 STRM。
2. 用文本编辑器打开这个 STRM，检查里面是完整的链接还是本地路径。
3. 如果是本地路径，确认 Emby 所在机器或容器能按这个路径读取原视频，见 [文件权限相关问题](文件权限相关问题.md)。
4. 如果是网络链接，从 **Emby 所在机器或容器** 访问它。只在自己电脑上打开链接，不能验证 Emby 的网络环境。

访问链接时，按结果继续处理：

| 结果 | 优先检查 |
| --- | --- |
| 无法连接、域名解析失败或证书错误 | 地址、端口映射、防火墙、DNS、证书和容器网络 |
| 返回 JSON 错误或提示账号、文件异常 | QMediaSync 中账号是否有效、原文件是否存在，以及同一时间的服务日志 |
| 已跳转，但后续视频请求失败 | 播放器是否能访问跳转目标，链接是否过期，以及请求头是否符合来源要求 |
| 能实际读取视频，但播放器仍失败 | 编码、音轨、字幕、媒体信息和客户端兼容性 |

HTTP `200` 也可能返回业务错误；`302`、`307` 跳转，或只探测不下载的请求成功，也不能证明视频真的能读取和播放。

## 2. 核对 STRM 地址和目录配置

对 115 网盘、百度网盘等由 QMediaSync 提供播放入口的来源，到“STRM 同步 → STRM 设置”检查“STRM 直连地址”。它通常是 QMediaSync 主服务地址，例如 `http://192.168.1.10:12333`，不是 Emby 的 `8096` 或代理的 `8095`。

同时检查同步目录是否开启“自定义 STRM 配置”。开启后，目录设置可能覆盖全局地址。

**修改并保存地址后，要重新同步对应目录，再检查实际 STRM 内容是否已经更新。** 不要只检查设置页里的值。

OpenList 的 STRM 默认指向 OpenList；应检查 OpenList 地址、路径、签名和最终下载地址，不能一律替换成 QMediaSync 地址。

## 3. 通过原 Emby 入口测试

连接原 Emby 地址，例如 `http://192.168.1.20:8096`，用选定的播放器播放同一部影片。

如果链接可以读取，但原 Emby 仍无法播放：

- 查看 Emby 同一时间的播放、转码日志，确认失败的是读取视频还是解码。
- 对可能与 User-Agent 有关的直链问题，可在 QMediaSync“STRM 同步 → STRM 设置”临时开启“启用本地代理播放”，保存后用原 Emby 入口对比。开启后视频可能经过 QMediaSync，需留意服务器带宽。
- 这个开关不是所有来源的统一修复方式，也不是 `8095` 代理播放的通用开关。百度网盘当前本来就经 QMediaSync 的本地代理处理。
- 如果启用后没有改善，按实际需要恢复设置，保留错误时间和日志继续定位，不要反复修改不相关选项。

## 4. 通过 QMediaSync 的 Emby 代理测试

如果原 Emby 能播，再检查代理入口，例如 `http://192.168.1.10:8095`。

1. 在 QMediaSync“系统设置 → Emby”确认已填写原 Emby 地址，点击“保存设置”并重启 QMediaSync。
2. 确认 QMediaSync 能访问原 Emby，也能访问 STRM 中的地址。
3. Docker 部署确认 `8095` 已映射；使用 HTTPS 时核对实际代理端口、域名与证书。
4. 确认播放器连接的是 QMediaSync 的代理地址，而不是原 Emby 地址。
5. 用同一部影片比较局域网和外网结果。

浏览器中可以打开开发者工具的“网络”面板，查看失败的具体请求和跳转目标；其他播放器则查看它自己的错误信息。不要固定寻找某个网盘 CDN 域名，域名会变化。

尤其注意：

- 115 取链失败时，日志可能出现“QMS 115 取链失败，回退原始链接”。如果原 STRM 链接是内网地址，外网播放器无法访问它；应先解决取链失败原因。
- 115 取链和实际读取要求 User-Agent 匹配。把签名链接复制到另一个浏览器后得到的结果，不一定能代表原播放器的请求。
- 直链播放要求播放器支持媒体格式。浏览器能播不能保证电视端或其他播放器能播，需要转码时使用原 Emby 入口测试。
- 百度网盘、OpenList 和本地来源的播放路径不同，详见 [Emby 外网 302](Emby外网302.md)。

## 5. 检查媒体信息

如果缺少时长、进度条或音轨信息，可以按 [Emby 媒体信息提取](Emby-媒体信息提取.md) 手动提取一次，再在 Emby 详情页确认结果。媒体信息提取不能修复不可达的链接，也不能让播放器支持原本不支持的编码。

## 仍然失败时提供哪些信息

提交 Issue 前，整理以下内容，方便复现：

- QMediaSync、Emby 和播放器的版本，以及 Docker、Windows、Linux 等安装方式。
- 来源是 115 网盘、百度网盘、OpenList 还是本地目录。
- 使用原 Emby 还是代理入口，局域网还是外网，同一部影片的对比结果。
- 准确的失败时间、客户端报错，以及对应时间的 QMediaSync 和 Emby 日志。
- STRM 使用哪一种地址或路径。说明结构即可，不要公开完整签名链接。

发送前遮盖 API Key、Token、Cookie、账号信息和带签名的播放地址。QMediaSync 主日志位于实际 `config` 目录下的 `logs/app.log`。
