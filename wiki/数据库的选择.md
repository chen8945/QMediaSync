QMediaSync 支持 SQLite 和 PostgreSQL。数据库用来保存账号、同步目录、任务记录和设置；视频文件仍在原来的网盘或本地目录中。

**想少维护一个服务，可以选 SQLite；已经有 PostgreSQL，或经常同时执行大量任务，可以选 PostgreSQL。** 两种数据库都支持 QMediaSync 的主要功能，不必仅因为使用 Windows、Linux、Docker 或飞牛就固定选择其中一种。

## 两种数据库有什么区别

| 对比 | SQLite | PostgreSQL |
| --- | --- | --- |
| 安装准备 | 无需另外安装数据库服务 | 需要单独部署 PostgreSQL 15 或更新版本 |
| 数据保存 | 配置目录中的数据库文件，默认名为 `qmediasync.db` | PostgreSQL 自己的数据目录 |
| 日常维护 | 配置较少，适合希望简单部署的用户 | 需要维护数据库服务、账号、网络和备份 |
| 多任务读写 | 当前版本会让业务数据库操作依次排队；大量同步或密集写入时，查询可能需要等待 | 可以使用多个数据库连接，更适合频繁并行执行任务的场景 |

程序默认提供 PostgreSQL 配置，但应用和 Docker 镜像都不包含 PostgreSQL 服务。如果选择 PostgreSQL，需要先准备可用的数据库连接。

## 第一次安装怎么选

- **希望尽快开始使用**：在首次配置向导中选择 SQLite。数据库文件保存在 QMediaSync 的 `config/` 目录内，保留这个目录即可保留文件。
- **已经有 PostgreSQL 服务**：填写已有服务的地址、端口、用户名、密码和数据库名。
- **希望新建 PostgreSQL 服务**：按 [Docker 安装](Docker安装.md)、[Windows 安装使用](Windows-安装使用.md) 或 [Linux 安装使用](Linux-安装使用.md) 中适用的方式准备数据库，再填写连接信息。

容器里的 `localhost` 指向当前容器。QMediaSync 和 PostgreSQL 分别运行在两个容器时，应填写同一 Docker 网络中的数据库服务名，或容器能够访问的数据库地址。

首次初始化失败时，程序会回滚本次初始化并停止启动。检查数据库地址、账号权限、目录权限和日志，排除问题后再启动；不要靠删除已有数据库来处理连接错误。

## 已经在使用，能换数据库吗

可以通过 QMediaSync 的备份和恢复功能，在 SQLite 与 PostgreSQL 之间迁移。

**只修改 `db.engine`、数据库文件名或 PostgreSQL 连接信息，不会把原有数据搬过去。** 指向空数据库后看到新的初始化页面，并不代表原数据库的数据已经迁移。

迁移前先做好数据库备份，并另外保留整个原 `config/` 目录，尤其是 `encryption.key`。数据库 ZIP 不包含这个密钥，也不包含配置文件或媒体文件。详细操作、恢复后的重启和核对步骤见 [备份与恢复](备份与恢复.md)。

如果原来使用的是旧版内嵌 PostgreSQL，请先看 [更新与旧版迁移](更新与旧版迁移.md)。当前版本不启动内嵌 PostgreSQL，也不会自动导入旧迁移包；不能直接改成外部 PostgreSQL 或 SQLite 就跳过迁移。

需要查看数据库连接字段、配置文件位置或日志位置，见 [配置文件](配置文件.md)。
