本文前半部分用于给 **QMediaSync 管理页面**配置域名和 HTTPS，例如 `https://qms.example.com`。给播放器使用的 Emby 入口请直接看本页末尾的 [Emby 代理入口的 HTTPS](#emby-代理入口的-https)，完整播放配置见 [Emby 外网 302](Emby外网302.md)。

## 配置前先确认

1. QMediaSync 已经能通过本机或局域网地址正常登录，例如 `http://192.168.1.10:12333`。
2. 准备一个域名，下面统一用 `qms.example.com` 举例；请替换成自己的域名。
3. 使用独立域名或子域名，把页面和 `/api/` 一起代理到 QMediaSync。不要只代理首页，也不要放在 `/qms/` 之类的子路径下。
4. 外部连接先到 Nginx 或 Caddy，再由代理连接 QMediaSync。后端 `12333` 只应允许可信代理或你的管理网络访问。

本文示例假设代理直接接收浏览器连接，并在代理上处理 HTTPS。这样 QMediaSync 仍使用内部 HTTP `12333`，不需要再给应用配置 `12332` 的证书。

### 代理应该连接哪个地址

| 部署方式 | 示例中的上游地址 |
| --- | --- |
| 代理和 QMediaSync 都直接运行在同一主机 | `127.0.0.1:12333` |
| 代理运行在宿主机，QMediaSync 运行在 Docker | 把端口绑定为 `127.0.0.1:12333:12333`，代理连接 `127.0.0.1:12333` |
| 代理和 QMediaSync 都在 Docker，且加入同一网络 | `qmediasync:12333`，服务名按实际修改 |
| 代理与 QMediaSync 在不同主机 | QMediaSync 的内网 IP 和端口，并限制该端口只对需要的主机开放 |

容器里的 `127.0.0.1` 指容器自己。代理容器不能用它连接另一个 QMediaSync 容器；Docker 网络连接方式见 [Docker 安装](Docker安装.md)。

程序按代理传来的原始 `Host` 和外部协议（`X-Forwarded-Proto`）识别请求，这两项是反代配置的关键：不对时，登录后的保存、删除等写入请求会被 `REQUEST_ORIGIN_INVALID` 拒绝，登录也可能异常。下文配置都基于这一点。转发头只在可信代理后面才可信，后端端口的访问范围需要由部署网络或防火墙控制。

## 使用 Nginx

先准备域名证书和私钥。把下面的域名、证书路径和上游地址改为自己的值，再加入 Nginx 已加载的站点配置，例如 `/etc/nginx/conf.d/qmediasync.conf`。

下面使用 Nginx 1.25.1 及以上的 `http2 on` 写法；旧版本把 `listen 443 ssl;` 和 `http2 on;` 两行合并为 `listen 443 ssl http2;`。语法见 [Nginx HTTP/2 模块说明](https://nginx.org/en/docs/http/ngx_http_v2_module.html)。

```nginx
server {
    listen 80;
    server_name qms.example.com;
    return 301 https://qms.example.com$request_uri;
}

server {
    listen 443 ssl;
    http2 on;
    server_name qms.example.com;

    ssl_certificate /etc/nginx/certs/qms.example.com/fullchain.pem;
    ssl_certificate_key /etc/nginx/certs/qms.example.com/privkey.pem;

    # 为上传数据库备份留出空间，应用仍会检查自己的文件大小限制。
    client_max_body_size 1025m;

    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header Connection "";

    # 实时事件、日志和任务详情需要及时传到浏览器。
    location ~ ^/api/(events/stream|logs/stream|sync/tasks/[^/]+/stream)$ {
        proxy_pass http://127.0.0.1:12333;
        proxy_buffering off;
        proxy_cache off;
        gzip off;
        proxy_read_timeout 1h;
    }

    location / {
        proxy_pass http://127.0.0.1:12333;
        proxy_cache off;
    }
}
```

保留示例中的 `Host`、`X-Forwarded-Proto` 和实时接口配置，确保登录、保存设置、日志和任务进度正常。相关指令见 [Nginx 反向代理模块说明](https://nginx.org/en/docs/http/ngx_http_proxy_module.html)。

保存后，先检查配置；只有检查通过，再重载服务：

```bash
sudo nginx -t && sudo systemctl reload nginx
```

这组命令适用于通过 systemd 管理的 Nginx；容器或 NAS 内置代理使用对应的检查和重载入口。

## 使用 Caddy

下面示例使用 Caddy 管理公开域名的证书。先把域名的 DNS 记录指向代理主机，并确保公网 `80` 和 `443` 能到达 Caddy。Caddy 的数据目录需要持久保存，证书申请和续期依赖它。详细条件见 [Caddy 自动 HTTPS 说明](https://caddyserver.com/docs/automatic-https)。

把下面内容加入 `Caddyfile`，替换域名和上游地址：

```caddyfile
qms.example.com {
    @sse path /api/events/stream /api/logs/stream /api/sync/tasks/*/stream

    handle @sse {
        reverse_proxy 127.0.0.1:12333 {
            flush_interval -1
        }
    }

    handle {
        reverse_proxy 127.0.0.1:12333
    }
}
```

Caddy 会为该域名处理 HTTPS 和 HTTP 跳转。连接内部 HTTP 上游时，默认保留原始 `Host`，并设置 `X-Forwarded-Proto`；`flush_interval -1` 让事件及时转发。行为见 [Caddy reverse_proxy 说明](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)。

如果使用官方 systemd 服务、配置位于 `/etc/caddy/Caddyfile`，先检查，再重载：

```bash
sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile && sudo systemctl reload caddy
```

容器部署使用对应容器中的配置路径和重载方式。

## 使用 NAS 内置代理或其他代理面板

按照下面的要求填写即可：

- 外部地址使用完整的 HTTPS 域名，页面和 API 一起转发。
- 目标地址使用 QMediaSync 可达的 HTTP 地址和端口。
- 保留原始 `Host`，包括用户实际访问的非默认端口。
- 让可信代理传递外部协议 `X-Forwarded-Proto: https`。
- 对实时事件、日志和任务详情关闭缓存、响应缓冲及压缩，并提供足够长的读取超时。
- 上传备份时，代理的请求体积限制不能小于准备上传的文件。

任务进度和实时日志使用 SSE，即服务器持续向浏览器发送更新的连接。

如果前面还有 CDN、网关或第二层代理，要逐层确认最终到达 QMediaSync 的协议仍是外部的 HTTPS，不能被中间的 HTTP 连接覆盖。只信任受控上游传来的转发头；不要直接照搬单层代理示例中的 `$scheme` 到多层代理的内部节点。

## 需要配置 trustedOrigins 吗

通常不需要。浏览器通过 `https://qms.example.com` 打开页面，API 也通过同一个域名访问，只要代理正确保留协议、域名和端口，就属于同源访问。

`trustedOrigins` 是主配置 `config/config.yaml` 中的额外可信来源列表，适用于你明确管理的额外浏览器来源。确实需要时使用精确的“协议 + 域名 + 端口”，例如：

```yaml
trustedOrigins:
  - https://another-controlled.example.com
  - https://qms.example.com:8443
```

修改后重启 QMediaSync。它不支持用 `*` 放开全部来源，也不用于把前端和 API 拆成两个域名部署。

## 配好后怎么检查

1. 打开 `https://你的域名`，确认浏览器没有证书错误，可以正常登录。
2. 刷新页面，再保存一次设置。能浏览但不能保存，通常需要继续检查请求来源或登录会话。
3. 打开日志页面，确认新日志及时出现；执行一个小范围同步任务，确认进度会继续更新。
4. 在浏览器开发者工具的“网络”中查看事件连接：响应类型应为 `text/event-stream`，连接持续打开属于正常现象。
5. 确认浏览器到代理使用 HTTP/2：开发者工具“网络”的协议列显示 `h2` 即可。HTTPS 下使用 HTTP/2 能减少多个页面的长连接互相排队；代理到 QMediaSync 使用 HTTP/1.1 不影响这一点。

常见问题：

| 现象 | 先检查什么 |
| --- | --- |
| `502 Bad Gateway` | QMediaSync 是否运行；代理使用的上游地址能否连通；容器里是否误用了 `127.0.0.1` |
| `REQUEST_ORIGIN_INVALID` 或“请求来源无效” | 原始 `Host`、外部端口和 `X-Forwarded-Proto` 是否传对；浏览器的 `Origin` 或 `Referer` 是否被拦截 |
| `CSRF_TOKEN_INVALID` | 先刷新页面重试，仍失败则重新登录 |
| 日志很久不动，然后一次出现很多 | 代理或前置 CDN 是否仍在缓冲、压缩或缓存 SSE |
| 上传备份出现 HTTP `413` | 代理请求体积限制是否过小 |
| 一开多个页面就卡住 | 浏览器连接是否仍为 HTTP/1.1，长连接是否占满可用连接 |

排查时记录请求路径、HTTP 状态和错误码即可；不要公开 Cookie、初始化码、API Key 或登录请求内容。


## Emby 代理入口的 HTTPS

这一节用于让播放器通过 `https://emby.example.com` 连接 **QMediaSync 的 Emby 代理端口 `8095`**。请为它使用独立子域名，不要把前面的管理页面域名直接改成播放入口。

先按 [Emby 外网 302](Emby外网302.md) 填好原 Emby 服务器地址，保存并重启 QMediaSync，确认用 QMediaSync 的局域网 IP 和端口 `8095` 能打开 Emby，例如 `http://192.168.1.10:8095`。然后配置 DNS 和 HTTPS 代理。

| 地址 | 用途 |
| --- | --- |
| `https://qms.example.com` → `12333` | QMediaSync 管理页面，使用 QMediaSync 管理员账号 |
| `https://emby.example.com` → `8095` | 播放器使用的 Emby 代理入口，使用原 Emby 账号 |
| 原 Emby 地址，例如 `http://192.168.1.20:8096` | 仍填在 QMediaSync 的“Emby 服务器地址”中，由 QMediaSync 回源访问 |
| STRM 直连地址，例如 `http://192.168.1.10:12333` | 仍使用 Emby 和 QMediaSync 都能访问的 QMediaSync 地址 |

新增的 `https://emby.example.com` 不替代后两项。尤其不要把“Emby 服务器地址”填成这个代理域名，否则可能反复代理回自己。

无论使用哪种反代工具，上游都指向 QMediaSync 的 `8095`：代理与 QMediaSync 在同一主机时用 `127.0.0.1:8095`，同一 Docker 网络时用 `qmediasync:8095`，宿主机代理连接 Docker 时可把端口绑定为 `127.0.0.1:8095:8095`。Emby 客户端会使用多种路径和 WebSocket 长连接，需要整站代理（不要只代理首页或单个播放接口）、透传 WebSocket 升级请求，并使用较长的读写超时，避免播放和长连接被切断；HTTPS 在外部代理终止时，无需启用 QMediaSync 内置的 `8094`。后端 `8095` 的访问范围按本页前面的网络说明控制。

### 检查 Emby HTTPS 入口

1. 打开 `https://emby.example.com`，显示的应是 Emby 页面并能用原 Emby 账号登录；若出现 QMediaSync 管理页面，说明上游误填成了 `12333`。
2. 在播放器中把服务器地址改为这个 HTTPS 域名，播放一段视频，尝试暂停、继续和拖动进度，再用实际外网设备测试一次。仍失败时，按 [Emby 无法播放问题的排查步骤](Emby-无法播放问题的排查步骤.md) 继续检查。
