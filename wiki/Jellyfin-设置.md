# Jellyfin 设置

入口在「系统设置 → 媒体库 → Jellyfin」。Emby、Jellyfin 各保存一台服务器的设置，可以同时启用。Jellyfin 页面和播放直接使用 Jellyfin 自身地址。

## 连接和媒体库同步

1. 在 Jellyfin 管理后台创建 API Key。
2. 在 QMediaSync 的 Jellyfin 标签开启「启用 Jellyfin」，填写 QMediaSync 能访问的 Jellyfin 地址和该密钥，再点击「保存设置」。地址可以包含反向代理子路径。
3. 查询媒体库，选择「全部媒体库」或需要同步的媒体库，开启「启用同步」并保存设置。
4. 点击「启动全量同步」，等待状态明确显示成功；失败时检查服务日志、地址、密钥和媒体库权限。
5. 需要周期校验时保存 Cron；手动全量与定时同步均需「启用同步」。默认 `0 * * * *` 每小时整点执行；「每日首次全量同步」开启后，当天首次成功全量之后使用增量同步。

全量同步把 Jellyfin 条目和文件关联保存到 QMediaSync，不会替 Jellyfin 扫描新影片。Playlists 播放列表和合集不作为 QMediaSync 的同步媒体库；其中引用的电影和剧集仍通过原媒体库处理。同名的普通电影或电视剧库不受影响。

关闭「启用 Jellyfin」会保留设置，停止本端后续媒体业务；Emby 和飞牛影视不受影响。切换标签保留未保存输入，提取和同步按钮使用当前标签已保存的设置。保存后出现应用警告或回读失败时，按提示核验；重新保存可重试应用。

查询媒体库或保存后刷新出现“清理已删除媒体库记录”警告时，本次库清单仍可用，但 QMediaSync 的旧库记录清理未完成；保存后的警告不表示配置保存失败。检查同一时间的服务日志，处理原因后重新查询媒体库。

## 让 STRM 同步后自动刷新 Jellyfin

先完成一次条目全量同步，建立媒体库与同步目录的关联，再开启「同步后刷新媒体库」并保存。

已保存的 STRM 同步目录新增 STRM 或元数据下载任务时，QMediaSync 会安排刷新相关媒体。上传后 STRM 实际新增或更新也会触发；临时手动同步不触发。[STRM Webhook](STRM-Webhook.md) 还需由调用方显式开启刷新。

刷新会等待相关同步和元数据下载结束；请求被接受后，仍需等待 Jellyfin 自身扫描完成。条目全量、增量同步只维护 QMediaSync 中的记录，不会触发 Jellyfin 扫库。新建媒体库或同步目录尚未关联时，先让 Jellyfin 扫描入库，再执行一次条目全量同步。

## 提取媒体信息

1. 确认 Jellyfin 中至少有一个用户允许访问全部媒体库，并开启媒体播放权限。
2. 保存有效连接和总开关后，点击「提取媒体信息」。它扫描全部媒体库，为缺少可用媒体信息的条目安排后台提取；不受媒体同步选库范围限制。
3. 在「上传下载 → 下载队列」查看来源为「Jellyfin 媒体信息提取」的任务。任务失败时先检查权限、媒体源和网络，再重试。

「入库后提取媒体信息」只控制收到新媒体事件后自动安排提取；关闭它仍可手动提取。提取用于让 Jellyfin 读取媒体流信息，不会把视频完整下载到 QMediaSync。已完成请求后可在 Jellyfin 条目详情中核验结果。

## 媒体和播放通知

在 Jellyfin 安装并配置 [官方 Webhook 插件](https://github.com/jellyfin/jellyfin-plugin-webhook)，按插件要求重启 Jellyfin。然后配置：

1. 添加 **Generic Destination**。
2. Webhook URL 填入 Jellyfin 可访问的 QMediaSync 地址，例如 `http://qmediasync:12333/jellyfin/webhook`。
3. 使用标准 JSON，开启 **Send All Properties**，设置请求头 `Content-Type: application/json`。不要使用自定义模板改写条目身份字段。
4. 在 QMediaSync 保持「通知链接鉴权」开启，为插件设置 `X-API-Key` 请求头，值为 QMediaSync 的 API Key；它与 Jellyfin API Key 不同。
5. 选择媒体新增、媒体移除、播放开始和播放停止事件，保存插件设置。先新增一个测试条目或开始播放，检查 QMediaSync 日志确认事件已到达。

需要接收消息时，在 Jellyfin 标签开启「发送媒体通知」并保存，再到「通知管理」启用渠道和对应媒体事件规则。两端共用已有渠道规则，消息标明产品；详见 [任务与通知](任务与通知.md)。关闭发送开关只停止消息，不关闭媒体索引、自动提取或联动删除。

媒体通知日志会注明“条目同步已完成”或“删除处理已完成”，名称显示为 `剧名 S01E06（ItemId ...）`；整季显示为 `剧名 S01`。删除处理完成表示本次通知已处理，实际删除或保留哪些文件，请查看同一通知的文件／目录结果。

## 联动删除网盘文件

QMediaSync 生成的 STRM，请先对同步目录执行一次完整同步，并在同步记录详情中确认「文件记录更新」显示「记录更新完成」。外部程序生成的 STRM，先按 [存放和挂载要求](Emby-联动删除网盘文件.md#外部-strm-与不同挂载路径) 配好账号、同步目录及文件读取权限。

让 Jellyfin 扫描入库后，完成本端条目全量同步和上文的插件通知配置，确认 Jellyfin 读取的 STRM 与 QMediaSync 中的同步目录及网盘文件对应。先保持联动删除关闭，使用可丢弃的测试媒体验证移除通知能送达；确认后，在 Jellyfin 标签开启「删除时联动删除网盘文件」并保存。

删除只处理先前已确认的文件或目录身份。官方插件的移除通知不带原文件路径；没有本端历史关联的条目不会因此删除网盘文件。只开启开关而未同步，或在关闭期间收到移除事件，不能靠稍后开启补删。

删除是实际网盘操作。电影、整季或整剧满足目录清理条件时，会删除整个网盘目录，**包括里面的陌生文件和子目录**；条件不足时只处理已确认的文件及附件。其他存活版本、其他季、共享文件和同步根会受到保护，单集和独立视频不执行整目录清理。

只想清理本地 STRM 时，请先关闭并保存；Jellyfin 扫描发现 STRM 消失也可能发出移除通知。来源能力、具体范围及结果查看见 [联动删除网盘文件](Emby-联动删除网盘文件.md)，在 Jellyfin 的对应标签完成设置和测试。两端引用同一物理文件时，各端只核对自身关联，不查询另一端作为保护；请自行安排共享文件的删除操作。

## 原配置和排障

如果原来在 Emby 设置中填写了 Jellyfin 地址，请在 Jellyfin 标签重新填写并保存，确认同步和通知后再处理原 Emby 设置。连接不会自动移动，Jellyfin 不能作为 Emby 302 或页面代理的上游。

连接失败时先检查 QMediaSync 到 Jellyfin 的地址、子路径、密钥和权限；提示产品不符时，确认地址属于当前标签。STRM 目录的读取与播放配置见 [生成 STRM](生成-STRM.md)，一般问题见 [常见问题](常见问题.md)。
