大部分日常设置都可以在网页中修改。只有数据库连接、监听端口等启动配置，才通常需要编辑 `config/config.yaml`。

## 哪些在网页改，哪些在文件里改

| 想修改的内容 | 修改位置 |
| --- | --- |
| 数据库类型、文件名或 PostgreSQL 连接 | 首次配置向导，或 `config/config.yaml` 的 `db` 部分 |
| QMediaSync 的 HTTP / HTTPS 监听地址 | `config/config.yaml` 的 `httpHost`、`httpsHost` |
| 视频大小、扩展名、排除规则、定时同步 | 网页「STRM 同步 → STRM 设置」；单个同步目录还可设置自己的规则 |
| TMDB、fanart.tv 等刮削服务密钥 | 网页「刮削 & 整理 → 刮削设置」 |
| 通知渠道、Server酱等通知服务密钥 | 网页「系统设置 → 通知管理」 |
| 日志等级和保留策略 | 网页「系统设置 → 日志设置」，也可以编辑文件中的 `log` 部分 |
| 管理员密码和两步验证 | 网页「系统设置 → 用户管理」；无法登录时使用管理员恢复命令 |

网页中的 STRM、刮削、通知和账号设置保存在数据库中。不要为了修改这些设置，向 YAML 文件添加同名字段。

## 配置文件在哪里

| 安装方式 | 配置目录 |
| --- | --- |
| Windows / Linux 发布包 | `QMediaSync` 可执行文件旁边的 `config/` |
| Docker | 容器内的 `/app/config`，对应安装时挂载的宿主机目录或数据卷 |

主配置文件名是 `config.yaml`，也兼容旧的 `config.yml`。两者同时存在时，程序优先读取 `config.yaml`；保存配置时也使用这个文件名。不要在两个文件中各改一部分。

## 修改前后怎么做

1. 确认正在使用的配置目录，保留原配置文件。涉及数据库切换或迁移时，先按 [备份与恢复](备份与恢复.md) 备份数据库及整个配置目录。
2. 安排好正在执行的同步、上传和下载，停止 QMediaSync，再编辑文件。
3. 使用纯文本编辑器，只修改需要调整的项目。YAML 使用空格缩进，不使用 Tab；同一级不能重复写两个 `db`、`log` 等键。
4. 保存后按原安装方式启动服务。只修改文件不会立即改变运行中的程序。
5. 打开网页，确认账号、同步目录和设置仍然正确；修改端口后使用新地址。启动失败时先查看容器、服务或程序日志，再检查 `config/logs/app.log`。

解析失败时，程序不会自动覆盖原文件，也不会因为 `config.yaml` 有错而改读 `config.yml`。根据错误中的行号检查缩进、重复键和引号；必要时还原修改前的配置文件。

## 可用的配置示例

下面是一份使用 SQLite 的配置示例，适合了解各部分的写法。**已有实例应保留自己的数据库连接和 `jwtSecret`，不要直接用整份示例覆盖现有文件。** 首次安装也可以直接通过网页向导生成配置，无需手工创建。

```yaml
db:
  engine: sqlite
  sqliteFile: qmediasync.db

httpHost: ":12333"
httpsHost: ":12332"
trustedOrigins: []

# 内存缓存大小，单位为字节；这里是 20 MiB。
cacheSize: 20971520

# 新实例留空时自动生成。已有实例请保留原值。
jwtSecret: ""

log:
  level: info
  maxSizeMB: 10
  maxBackups: 3
  maxAgeDays: 7
  app: logs/app.log
  v115: logs/115.log
  openList: logs/openList.log
  tmdb: logs/tmdb.log
  baiduPan: logs/baidupan.log
  web: logs/web.log
  syncLogDir: logs/sync

strm:
  # 网页全局扩展名列表为空时，才使用这里的列表。
  # 这里也为空时，使用程序内置的默认扩展名。
  videoExt: []
  metaExt: []

emby302:
  insecure_skip_verify: false
  images_original: false

# 授权服务地址和应用标识，通常保持默认即可。
authServer: https://api.mqfamily.top
newAuthServer: https://oauth.qmediasync.cn
baiDuPanAppId: QMediaSync
```

`sqliteFile` 是 SQLite 数据库文件名，通常保留 `qmediasync.db` 即可，无需在前面加 `config/`。使用 PostgreSQL 时，这个字段不参与数据库连接。

### 使用 PostgreSQL

将示例中的 `db` 部分替换为下面的内容，并填写真实连接信息。当前版本需要单独部署 PostgreSQL 15 或更新版本，选择建议见 [数据库的选择](数据库的选择.md)。

```yaml
db:
  engine: postgres
  sqliteFile: qmediasync.db
  postgresConfig:
    host: localhost
    port: 5432
    user: qms
    password: "替换为数据库密码"
    database: qms
    ssl: false
    maxOpenConns: 25
    maxIdleConns: 25
```

- `host` 不带 `http://` 或 `https://`。`localhost` 只适合数据库就在当前主机或容器内的情况；两个独立容器通常填写数据库服务名，具体见 [Docker 安装](Docker安装.md)。
- `database` 是 QMediaSync 使用的数据库名。数据库不存在时，程序会尝试创建，但连接账号必须有相应权限；也可以先由数据库管理员创建。
- `ssl: true` 使用 PostgreSQL 的 `sslmode=require`，要求加密连接；它不是网页的 HTTPS 开关。
- `maxOpenConns` 和 `maxIdleConns` 只影响 PostgreSQL，通常保持示例值即可。SQLite 的业务连接固定为一个，不能靠这两个参数增加并发。
- 数据库连接只从这个文件读取，旧的 `DB_HOST`、`DB_PORT`、`DB_USER` 等环境变量不再用于配置数据库。

新配置不需要 `postgresType`。旧 PostgreSQL 配置中的 `external` 或缺省值仍可使用，`embedded` 会被拒绝。旧内嵌数据库的处理步骤见 [更新与旧版迁移](更新与旧版迁移.md)。

**修改数据库类型、文件名或连接信息不会迁移数据。** 已有数据需要保留时，请先完成 [备份与恢复](备份与恢复.md) 中的迁移流程。

### 端口、HTTPS 和反向代理

- `httpHost: ":12333"` 表示在 HTTP `12333` 端口提供网页服务。
- `httpsHost: ":12332"` 是内置 HTTPS 的监听地址。发布包和 Docker 部署还需要在 `config/` 放入有效的 `server.crt` 和 `server.key`，只有端口配置而没有证书不会开启 HTTPS。
- Docker 还要检查端口映射。例如只想通过宿主机的 `12334` 访问，通常把映射改为 `12334:12333`，容器内的 `httpHost` 保持原值；更改映射后需重新创建容器。
- Emby 302 默认使用 HTTP `8095` 和 HTTPS `8094`，与 QMediaSync 网页端口不同，详见 [Emby 外网 302](Emby外网302.md)。

`trustedOrigins` 用于你明确管理的额外浏览器来源。普通安装或通过同一个反向代理域名访问网页和 API 时，保持 `[]` 即可；不要仅因为用了域名或 HTTPS 就添加它。确实需要添加额外来源时填写完整的“协议 + 域名 + 端口”，例如 `https://qms.example.com`，不带页面路径。它不能代替同源部署，当前前端、API 和实时事件连接仍应通过同一个来源访问；完整代理示例见 [反向代理配置](反向代理配置.md)。

### STRM 设置的生效顺序

调整视频最小体积、定时同步和过滤规则时，请进入「STRM 同步 → STRM 设置」，操作示例见 [生成 STRM](生成-STRM.md)。

旧配置里可能仍有 `strm.minVideoSize` 和 `strm.cron`。当前版本加载时会将它们重置为 `100` 和 `30 * * * *`，**不能通过修改这两个 YAML 值来调整网页中的最小文件大小或定时任务**。

视频扩展名和元数据扩展名按各自的列表分别取值：

1. 同步目录配置了非空自定义列表时，使用这个列表。
2. 目录列表为空时，继承网页中的全局列表。
3. 网页全局列表也为空时，使用 YAML 中的 `strm.videoExt` 或 `strm.metaExt`。
4. YAML 列表仍为空时，使用程序内置默认值。

内置视频扩展名为 `.mp4`、`.mkv`、`.avi`、`.mov`、`.wmv`、`.flv`、`.webm`、`.m4v`、`.3gp`、`.ts`；元数据扩展名为 `.jpg`、`.jpeg`、`.png`、`.webp`、`.nfo`、`.srt`、`.ass`、`.svg`、`.sup`、`.lrc`。

因此，清空全局扩展名列表并保存，不表示关闭文件识别。需要增加扩展名时，直接在网页全局设置或同步目录中添加，更容易确认实际生效的内容。

### 日志

默认日志位于 `config/logs/`。常用文件如下：

| 文件 | 查看什么 |
| --- | --- |
| `app.log` | 启动、数据库、网页请求和 Emby 302 等通用问题 |
| `115.log` | 115 网盘请求和请求队列 |
| `openList.log` | OpenList 请求 |
| `tmdb.log` | TMDB 刮削请求 |
| `baidupan.log` | 百度网盘请求 |
| `sync/` | 各次同步任务的独立日志 |

`log.level` 可选 `debug`、`info`、`warn`、`error`，日常使用 `info`。排查问题时可在「系统设置 → 日志设置」临时改成 `debug`，复现后再改回。在网页中保存会立即生效，并写回配置文件，无需重启。

`maxSizeMB` 默认 `10`，表示单个轮转日志文件最大约 10 MB；`maxBackups` 默认 `3`，表示每个日志最多保留 3 个轮转备份；`maxAgeDays` 默认 `7`，表示轮转备份最长保留 7 天。同步任务日志另随同步记录清理，不使用这些轮转规则。`web` 是预留配置，通用网页日志主要看 `app.log`。

提交问题时只提供相关时间段，并先检查是否包含密码、Token、Cookie 或带签名的下载链接。

### 第三方密钥与需要保留的文件

TMDB、fanart.tv 和 AI 识别服务优先在网页中配置。只有需要通过部署环境提供默认值时，才使用以下变量：

| 变量 | 用途 |
| --- | --- |
| `TMDB_API_KEY` | TMDB API Key |
| `TMDB_ACCESS_TOKEN` | TMDB API 访问令牌 |
| `FANART_API_KEY` | fanart.tv API Key |
| `SC_API_KEY` | AI 辅助识别的默认 API Key，仅在该模式下未填写 AI 密钥时使用 |

Docker 和 Windows / Linux 发布包中，取值顺序是：**网页中保存的值 → 程序旁的 `config/.env` → 进程环境变量 → 程序自带默认值**。这个 `.env` 会覆盖同名环境变量；发现环境变量修改后没有生效时，也要检查网页设置和这个文件。

Server酱的 `SCKEY` 在通知渠道中单独填写，和 `SC_API_KEY` 不是同一项。通知配置步骤见 [任务与通知](任务与通知.md)。

下面的 `.env` 写法适用于上述 Docker 和发布包布局。日常使用的第三方密钥优先在网页设置中填写，`.env` 仅作为备选方式。

`config/.env` 每行写一个 `名称=值`，例如：

```dotenv
TMDB_API_KEY=替换为自己的密钥
FANART_API_KEY=替换为自己的密钥
```

不要添加 `export`，也不要在值外加引号。修改这个文件或进程环境变量后需要重启 QMediaSync。它与 Docker Compose 用于变量替换的项目级 `.env` 不是同一个文件。

`jwtSecret` 用来保护网页登录会话，新实例留空时会自动生成并写回配置。已有实例应保留原值，修改它会使现有登录失效。管理员账号和密码不写在 YAML 中，初始化和密码恢复见 [管理员与密码恢复](管理员与密码恢复.md)。

`config/encryption.key` 是每个实例生成的本机加密密钥，用于两步验证等敏感数据。**备份、升级和迁移时必须保留它；数据库备份 ZIP 无法补回丢失的密钥。** 保留整个 `config/` 的操作见 [备份与恢复](备份与恢复.md)，目录无法写入时见 [文件权限相关问题](文件权限相关问题.md)。

### Emby 302 图片与证书

`emby302.images_original: true` 会请求 Emby 海报、背景等图片的原图，修改后重启生效。它会移除缩放和部分图片处理参数，也会关闭 Emby 图片上的播放标记等叠加效果；图片流量和加载时间可能增加。

`emby302.insecure_skip_verify` 默认 `false`。只有明确需要访问受控内网的自签名 HTTPS 服务，或临时排查证书问题时，才考虑设为 `true`；启用后将跳过出站 HTTPS 证书校验，不适合长期用于公网服务。常规代理和播放排查见 [Emby 外网 302](Emby外网302.md) 与 [Emby 无法播放问题的排查步骤](Emby-无法播放问题的排查步骤.md)。
