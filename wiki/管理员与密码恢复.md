QMediaSync 的管理员在网页中创建和管理，不写在 `config.yaml` 中。忘记密码或丢失两步验证设备时，可以在部署主机上重置管理员密码，网盘账号、同步目录和业务数据会保留。

## 第一次创建管理员

1. 按安装页完成数据库配置并启动 QMediaSync。
2. 在这一轮启动日志中找到「初始化码」。Docker Compose 可在原部署目录执行 `docker compose logs --tail=100 qmediasync`；Linux systemd 可执行 `sudo journalctl -u qmediasync -n 100 --no-pager`；Windows 可查看程序旁的 `config/logs/app.log`。日志路径改过时使用实际路径。
3. 等待服务启动完成，在浏览器打开 QMediaSync；如果仍停留在数据库配置成功提示页，需手动刷新当前页面。填写初始化码、管理员用户名、密码和确认密码，点击「创建管理员」。
4. 创建成功后使用该账号登录。初始化码随即失效；尚未创建管理员就重启程序时，要使用新一轮启动日志里的码。

用户名须为 `3` 到 `20` 个英文字母或数字；密码至少 `6` 个字符，不能全是数字或全是字母。建议使用密码管理器生成并保存密码。没有统一的默认管理员密码。

## 仍能登录时修改密码

打开「系统设置 → 用户管理」，填写新的「密码」和「确认密码」，点击「保存设置」。修改用户名时在同一页面操作；只改用户名可将密码留空。

用户名或密码修改成功后，所有浏览器都需要重新登录，已有 QMediaSync API Key 会保留。新密码不能与当前密码相同。

## 启用两步验证

两步验证使用 TOTP，也就是验证器中不断变化的动态验证码。

1. 打开「系统设置 → 用户管理」，找到「两步验证」，点击「生成配置」。
2. 用支持 TOTP 的验证器扫描二维码，或手动录入页面显示的密钥。
3. 在页面输入验证器当前显示的 `6` 位验证码，点击「启用两步验证」。只有确认成功才算启用。
4. 妥善保管验证器及其备份，同时保存原 `config/`，尤其是 `encryption.key`。之后登录需要密码和当前验证码。

关闭两步验证需要当前密码和当前动态验证码。启用或关闭后，其他浏览器需要重新登录，当前操作的浏览器会保留登录状态。

QMediaSync 没有网页恢复码。无法取得验证码时，使用下面的本地密码恢复；如果只是验证码一直不通过，先检查手机与服务器的系统时间，再按页面提示等待登录限制解除，避免连续尝试。

## 选哪种恢复方式

| 操作 | 会发生什么 | 适用情况 |
| --- | --- | --- |
| 重置密码 | 保留用户名，生成随机新密码，关闭两步验证，退出所有浏览器；保留 QMediaSync API Key 和全部业务数据 | 忘记密码或无法完成两步验证，优先选这一项 |
| 删除管理员 | 删除管理员，清除全部浏览器会话和 QMediaSync API Key；保留网盘账号、同步目录、设置及其他业务数据 | 确实需要重新创建管理员 |

删除管理员后，原有 Webhook 等集成使用的 QMediaSync API Key 会失效，需要重新创建并更新到调用方。它不会把程序恢复为出厂状态。

恢复要在部署主机上执行，需要访问原配置目录。操作期间 QMediaSync 会停服，先安排好同步、上传和下载，并保存已有配置和数据库。**所有连接同一数据库的 QMediaSync 实例都必须停止**；PostgreSQL 服务本身应继续运行。

## Docker Compose：用恢复脚本处理停启

适用于标准镜像布局，程序位于容器 `/app/QMediaSync`，配置通过可写挂载保存在 `/app/config`。需要 Bash、Docker Compose `2.24.4` 或更新版本、`curl`、`tar`、`awk`，以及访问 Docker 的权限。

1. 在**原 Compose 文件所在目录**打开终端，确认这里就是运行中实例的部署目录。
2. 下载恢复脚本并执行：

```bash
curl -fsSL https://raw.githubusercontent.com/chen8945/QMediaSync/main/scripts/recover-admin.sh -o recover-admin.sh
bash recover-admin.sh --action reset-password
```

3. 如果出现服务选择列表，按编号选择 QMediaSync 容器。脚本会先检查实际部署，再停止这个容器、执行恢复。其他服务，包括 PostgreSQL，不会被停止。
4. 保存终端最后显示的用户名和新密码。原容器之前在运行，脚本会尝试启动原容器；原来就停止的容器会保持停止，需要自行启动。
5. 打开网页，用原用户名和新密码登录，检查业务配置，然后按需要重新启用两步验证。

不指定 `-f` 时，脚本只在当前目录按常见 Compose 文件名查找，不会到父目录或脚本目录猜测部署。

原部署使用多个文件、项目名或环境文件时，恢复时也要完整指定，例如：

```bash
bash recover-admin.sh \
  -f compose.yaml -f compose.production.yaml \
  -p qmediasync --env-file .env.production \
  --service qmediasync --action reset-password
```

示例里的文件名、项目名和服务名要替换成原部署实际使用的值。使用 `COMPOSE_FILE` 的部署同样要通过 `-f` 写明全部文件；没有交互终端时用 `--service` 指定目标。

脚本会先核对实际部署，提示不一致时先核对原部署，不要临时改一份配置绕过检查；脚本不会拉取新镜像或重建服务。使用卷子目录挂载的部署，改用后面的非 Compose 方式并保留原挂载写法。

恢复成功但容器启动失败时，脚本仍会显示新密码。先保存它，再处理启动问题；不要因为启动失败就把已完成的密码重置当作没生效。

## Linux 发布版

在放有 `QMediaSync` 的目录操作。恢复命令必须使用原服务的运行用户和原 `config/`；自定义服务名或配置位置时替换示例值。

使用 `qmediasync.service` 的部署，先停止服务并查看运行用户：

```bash
sudo systemctl stop qmediasync
systemctl show qmediasync -p User
```

输出 `User=alice` 表示原服务以 `alice` 运行；`User=` 为空时，systemd 默认使用 root。确认自己就是原运行用户后执行：

```bash
./QMediaSync --reset-admin-password
```

当前用户不同时，用 `sudo -u 实际运行用户名 ./QMediaSync --reset-admin-password`。配置不在程序旁时，显式指定已有目录：

```bash
./QMediaSync --reset-admin-password --config-dir /实际配置目录/config
```

保存输出的新密码后启动并检查服务：

```bash
sudo systemctl start qmediasync
systemctl status qmediasync --no-pager
```

如果原来直接运行程序，没有 systemd 服务，先关闭原进程，执行一次恢复，再按原来的方式启动。恢复参数只用这一次，不要写进开机启动命令。

## Windows 发布版

1. 从托盘退出 QMediaSync，确认程序已经结束。
2. 在 `QMediaSync.exe` 所在目录打开 PowerShell，执行：

```powershell
.\QMediaSync.exe --reset-admin-password
```

3. 恢复结果通过 Windows 系统窗口显示。先保存用户名和新密码；窗口有焦点时可按 `Ctrl+C` 复制内容。
4. 关闭结果窗口，重新打开 `QMediaSync.exe`，用新密码登录。

自定义配置目录时可以这样指定：

```powershell
.\QMediaSync.exe --reset-admin-password --config-dir "D:\QMediaSync\config"
```

此方式需要可交互的 Windows 桌面，不适用于看不到窗口的无人值守服务会话。

## 非 Compose 的 Docker 部署

未使用 Compose 的 Docker 部署，应先停止原 QMediaSync 容器，再使用**原版本镜像、原配置挂载、原数据库网络，以及原来的用户/组 ID（UID/GID）**执行一次性恢复。下面是需替换参数的示例：

```bash
docker stop 原QMediaSync容器名

docker run --rm --log-driver none --network 原数据库网络 \
  --user 原UID:原GID \
  --mount type=bind,src=/实际配置目录,dst=/app/config \
  --entrypoint /app/QMediaSync \
  ghcr.io/chen8945/qmediasync:实际版本 --reset-admin-password
```

命名卷、卷子目录或自定义目录部署应保留原挂载方式，不要照抄成另一份空目录。保存新密码后用 `docker start 原QMediaSync容器名` 启动并检查。不要在仍运行的原容器中直接用 `docker exec` 重置。

## 确实需要删除管理员时

先阅读本页表格中的影响，并按对应部署方式停止全部 QMediaSync 实例。Docker Compose 使用同一脚本：

```bash
bash recover-admin.sh --action delete-admin
```

脚本会要求输入 `DELETE` 确认。其他选项与重置密码相同。

Linux 发布版使用：

```bash
./QMediaSync --delete-admin --yes
```

Windows 发布版使用：

```powershell
.\QMediaSync.exe --delete-admin --yes
```

有自定义配置目录时仍需加 `--config-dir`。命令完成后按原部署方式启动服务，从**新一轮启动日志**取得初始化码，按本页「第一次创建管理员」重新创建。最后重新配置两步验证，并重新创建外部集成需要的 QMediaSync API Key。

## 恢复失败时检查什么

| 提示或现象 | 下一步 |
| --- | --- |
| 配置目录正在使用或无法加锁 | 确认原程序和其他实例已停止，不要手动删除正在使用的 `.qmediasync.lock` 文件 |
| 配置文件或数据库不存在 | 检查是否选错目录、挂载或数据库连接；恢复命令不会新建数据库 |
| 检测到内嵌 PostgreSQL 或 `backups/migrate.zip` | 按 [更新与旧版迁移](更新与旧版迁移.md) 处理旧状态，不靠删除迁移包跳过检查 |
| 没有管理员 | 正常启动程序，使用初始化码创建管理员 |
| 提示账号数据（认证表）缺失，或存在多个管理员 | 保留数据库和日志，先核查升级或数据异常；恢复命令不会自行修复 |
| 关闭窗口后忘了保存新密码 | 新密码不写入应用日志，需要重新执行密码重置 |

恢复只处理管理员登录，不会重新授权网盘，也不会修复数据库文件。备份恢复请看 [备份与恢复](备份与恢复.md)。
