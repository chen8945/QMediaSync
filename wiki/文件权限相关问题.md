遇到“权限不足”“permission denied”、STRM 写入失败或 Emby 无法读取文件时，先确认**哪个程序，以哪个用户，访问哪个路径**。给所有目录开放全部权限通常解决不了路径映射错误，还会暴露配置和密钥。

## 先分清运行用户和目录

| 运行方式 | QMediaSync 使用哪个用户 |
| --- | --- |
| Linux 直接运行 | 启动程序的用户；使用 systemd 时以服务配置为准，不一定是 root |
| Docker | 默认入口先以 root 完成初始化；设置 `GUID` 后，再以对应用户运行主程序 |
| Windows | 启动程序的 Windows 用户 |

Linux 的 `--guid` 参数不会把进程切换成另一个用户。Docker 的 `GUID` 是用户 ID，`GPID` 是组 ID；它们是 QMediaSync 镜像使用的变量名，不要替换成其他镜像常见的 `PUID`、`PGID`。

不同目录需要的权限也不同：

- **配置目录**：QMediaSync 需要读写，Docker 中是 `/app/config`，直接运行时是程序同级的 `config`。
- **STRM、字幕、海报等输出目录**：QMediaSync 需要创建、修改文件；启用清理时还需要删除权限。
- **媒体源目录**：只读取时需要读取权限；整理、移动或删除文件时，还需要相应目录的写入权限。
- **Emby 使用的目录**：Emby 需要读取 STRM 和实际视频，并能进入路径中的各级目录。需要从 Emby 删除文件时，通常还需要文件所在目录的写入权限。

## Docker 中设置用户

先在宿主机上，以准备运行和管理这些文件的用户执行：

```bash
id -u
id -g
```

第一行是用户 ID，第二行是组 ID。不要直接把某台 NAS 的示例数字当成所有设备的默认值。

例如，查询结果分别是 `1000` 和 `1001`，就在 QMediaSync 的 Compose 服务中加入：

```yaml
environment:
  GUID: "1000"
  GPID: "1001"
```

替换成自己的查询结果，保存后重新创建容器。不要用 Compose 的 `user:` 或 `docker run --user` 代替这一步，否则默认入口可能无法创建用户或修正配置目录的所有者。

默认入口会在首次记录用户、或 `GUID` / `GPID` 变化时修正 `/app/config` 的所有者。它**不会自动修改媒体挂载目录**的所有者，也不会在每次启动时重新修复所有文件权限。

## 修正已有媒体目录的所有者

先检查挂载关系。例如：

```yaml
volumes:
  - /srv/qmediasync/config:/app/config
  - /srv/qmediasync/media:/media
```

冒号左边是宿主机路径，右边是容器内路径。QMediaSync 页面中填写 `/media`；在宿主机上检查和修改的则是 `/srv/qmediasync/media`。

```bash
ls -ld /srv/qmediasync/media
```

如果这个目录专门供 QMediaSync 使用，且确认应由 `1000:1001` 管理，可以在宿主机执行：

```bash
sudo chown -R 1000:1001 /srv/qmediasync/media
```

把数字和路径换成实际值。命令会修改该目录及其所有内容的所有者；共享给其他应用的媒体目录，应先确认它们仍可访问，或通过共同的用户组、NAS 权限设置授权，不要直接修改整个磁盘或共享根目录。

如果所有者正确却仍然无法写入，再检查挂载是否为只读、NAS 共享权限和 ACL，以及上级目录是否允许该用户进入。

## 配置目录不要统一改成 777

`config` 中有数据库配置、账号相关数据和本机加密密钥。`encryption.key` 创建时的权限是 `0600`，也就是仅允许所有者读取和写入；其中部分私有目录也有更严格的权限要求。

遇到配置目录权限错误时，先停止程序，确认目录属于实际运行用户，再修正所有者。保留文件原有权限，不要对整个 `config` 执行递归 `chmod`，也不要删除密钥重新生成。需要迁移或恢复时见 [备份与恢复](备份与恢复.md)。

## 与 Emby 共用目录

Emby 的 Docker 镜像不一定使用相同的用户变量，具体变量应按所用镜像的说明设置，不能照抄 QMediaSync 的 `GUID` / `GPID`。

两者不一定必须使用同一个用户，关键是各自有需要的访问权限。只有“能看到 STRM”还不够：本地目录生成的 STRM 保存的是视频路径，Emby 也必须能按这个路径读到视频。例如 STRM 中写的是 `/media/movies/example.mkv`，Emby 容器里这个路径必须存在并可读；宿主机路径可以不同。

详细挂载示例见 [生成 STRM](生成-STRM.md)。权限确认无误后仍不能播放，继续看 [Emby 无法播放问题的排查步骤](Emby-无法播放问题的排查步骤.md)。
