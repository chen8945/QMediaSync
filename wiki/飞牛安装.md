本文介绍通过飞牛 fnOS 应用中心安装和管理 QMediaSync。若准备在飞牛上使用 Docker，请阅读 [Docker 安装](Docker安装.md)；两种方式的目录和权限设置不同。

## 1. 选择安装包

先查看你的飞牛设备架构，并在 [QMediaSync 发布页面](https://github.com/chen8945/QMediaSync/releases) 的附件中查找对应的 FPK：

| 设备架构 | 安装包 |
| --- | --- |
| x86-64，常见 Intel 或 AMD 设备 | `QMediaSync_fnos_x86_64.fpk` |
| ARM64 | `QMediaSync_fnos_arm64.fpk` |

并非每个版本都提供 FPK，以该次发布的附件为准。没有 FPK 时，可以改用 [Docker 安装](Docker安装.md)，不要把 Linux 压缩包当作 FPK 上传。

如果你的应用中心提供 QMediaSync，先核对应用介绍中的项目来源和版本；本页不假定某个版本已在应用中心上架。已有对应 FPK 时，可打开应用中心的“手动安装”，选择 `.fpk` 文件并按向导继续；手动安装入口见 [飞牛官方应用安装说明](https://developer.fnnas.com/docs/quick-started/test-application/)。

## 2. 在网页配置数据库

fnOS 安装向导只说明安装后如何开始使用，不填写数据库连接信息。安装并启动后，从桌面入口打开 QMediaSync，或使用飞牛的局域网 IP 访问，例如 `http://192.168.1.10:12333`。

全新安装会进入 QMediaSync 的数据库配置页面；已有配置会继续使用，不需要重新选择数据库。升级或保留数据后重装却出现首次配置页面时，先检查原配置目录，不要急着重新初始化。

如果启动日志提示“fnOS 配置迁移尚未完成”，请先停止应用，分别备份日志中列出的旧目录和共享目录；确认原配置、加密密钥和数据库等文件完整后再按日志提示处理，不要直接删除标记或重新初始化。不确定怎样恢复时，请保留两份目录并寻求帮助。

如果提示配置目录正在使用，先停止占用它的其他实例；正在恢复时，等待恢复结束后再启动应用。

- **SQLite**：不需要安装数据库服务，在网页选择后按提示确认即可。
- **PostgreSQL**：先准备 PostgreSQL 15 及以上服务，再填写实际连接信息并点击“测试连接”，成功后保存。应用本身不会替你安装 PostgreSQL。

选择依据见 [数据库的选择](数据库的选择.md)。

选择 PostgreSQL 时填写：

| 项目 | 填写内容 |
| --- | --- |
| 主机地址 | 数据库所在主机的可达 IP 或域名 |
| 端口号 | 数据库实际监听或发布的端口 |
| 用户名 | 有权访问 QMediaSync 数据库的用户 |
| 密码 | 该数据库用户的实际密码 |
| 数据库名称 | QMediaSync 使用的独立数据库名，例如 `qmediasync` |
| SSL | 按数据库实际配置填写；未配置 TLS 时保持关闭 |

如果 PostgreSQL 在同一台飞牛设备的 Docker 中，按 [Docker 安装](Docker安装.md) 页面末尾的独立数据库示例部署后，主机填 `127.0.0.1`，端口填 `15432`。FPK 应用运行在宿主机上，不能直接使用 Docker 网络里的 `postgres` 服务名。

如果测试提示已有数据库包含数据，需要保留就选择“取消”；选择“确定”会尝试删除并重建数据库。不要使用其他应用的数据库。

保存成功后会自动启动 QMediaSync。请等待启动完成，再按下一节查看初始化码并手动刷新网页；页面不会自动跳转。

如果提示“配置已保存，但未能自动启动”，配置已经保留，可按页面提示重试保存；仍失败时，在飞牛应用中心停止后重新启动 QMediaSync。如果提示保存失败，先根据页面说明检查配置目录权限或数据库连接，再重试。

## 3. 启动并创建管理员

1. 在飞牛文件管理器找到应用共享目录 `qmediasync`，打开其中的 `config/logs/app.log`。不同存储空间的完整路径可能不同，不要照搬别人的 `/vol1/...` 路径。
2. 在最新一次启动日志中找到“检测到系统尚未创建管理员，请使用以下初始化码完成首次管理员创建”，复制后面的初始化码。
3. 刷新 QMediaSync 网页，在“创建管理员”表单中填写初始化码、用户名和密码。用户名为 3～20 个英文字母或数字；密码至少 6 个字符，不能是纯数字或纯字母。
4. 创建成功后，使用新账号登录，再按 [快速开始](快速开始.md) 完成基础设置。

初始化码只在本次启动期间有效。创建前重启过应用，就需要从最新日志重新取码；已有管理员时不会再生成初始化码。

如果找不到共享目录或日志，查看应用启动输出中的“当前配置文件目录”，以该路径为准。正常情况下配置位于应用共享目录的 `config/`，旧安装或平台未提供共享路径时可能使用平台配置目录。首次初始化请在可信的局域网内完成。

## 4. 授权媒体目录

1. 在飞牛应用中心找到 QMediaSync，打开应用设置中的目录访问授权。
2. 授权需要使用的目录：生成 STRM、图片和 NFO 的目标目录需要写入权限；只读取本地挂载文件的来源目录至少需要读取权限。启用源文件删除等功能时，来源也需要相应写入权限。
3. 回到 QMediaSync，在本地目录选择器点击“刷新”，确认已授权的目录能够显示。仍未生效时，在飞牛应用中心停止后启动 QMediaSync，再试一次。
4. 如果 Emby 也要读取生成的文件，再单独给 Emby 授权对应目录。

原生 fnOS 的本地目录选择器会显示授权检查说明，网盘目录不显示。QMediaSync 没有额外的应用内授权入口，目录授权仍在 fnOS 应用设置完成。

飞牛应用通过平台管理访问权限，具体机制见 [飞牛官方权限说明](https://developer.fnnas.com/docs/core-concepts/privilege/)。无需给 FPK 应用设置 Docker 的 `GUID`、`GPID` 或 `/app/config` 挂载。在 fnOS 上使用 Docker 的用户仍按容器挂载和用户权限配置。目录仍不可写时，见 [文件权限相关问题](文件权限相关问题.md)。

## 数据放在哪里

| 内容 | 位置和用途 |
| --- | --- |
| 主配置 | 实际配置目录中的 `config.yaml` |
| SQLite 数据库 | 默认是配置目录中的 `qmediasync.db` |
| 本机加密密钥 | 配置目录中的 `encryption.key`，迁移时必须保留 |
| 日志 | 配置目录中的 `logs/`，主日志默认是 `app.log` |
| STRM 和元数据 | 你在同步目录中选择的目标路径 |
| PostgreSQL 数据 | 独立数据库服务的数据目录，不在 FPK 安装目录中 |

共享目录由飞牛按安装位置创建，应用可以通过平台提供的路径访问。见 [飞牛官方共享目录说明](https://developer.fnnas.com/docs/core-concepts/resource/)。备份时保留整个配置目录，并按 [备份与恢复](备份与恢复.md) 备份数据库；单独保留 FPK 安装包不能恢复账号和同步设置。

## 停止、重启、更新和卸载

日常启停在飞牛应用中心操作。需要重启或备份恢复完成后，停止再启动 QMediaSync。

应用中心安装的版本，在应用中心更新；手动安装的版本，下载对应架构的较新 FPK，在应用中心选择“手动安装”并上传即可升级，无需先卸载。相同或更低版本会被平台拒绝。需要保留回退能力时，提前按 [更新与旧版迁移](更新与旧版迁移.md) 保存数据库和配置。

卸载向导默认选择“保留数据，重新安装后可继续使用”。选择删除会移除应用共享目录下的 `config/`；其中可能包含 SQLite 数据库、密钥和本地备份。需要继续使用原数据时保留默认选项，并提前把备份复制到应用目录以外。删除操作不处理外部 PostgreSQL 数据和自选媒体目录中的文件，这些内容需要分别管理。

安装完成后，检查能否登录、是否能在授权目录写入 STRM，以及重启后配置是否保留。忘记密码见 [管理员与密码恢复](管理员与密码恢复.md)，管理页面的 HTTPS 和域名配置见 [反向代理配置](反向代理配置.md)。
