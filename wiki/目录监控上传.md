# 目录监控上传

目录监控上传用于把本地新文件自动上传到 **115 网盘**，再生成本地 STRM。例如，下载工具把电影放进一个本地目录后，QMediaSync 自动把它送到网盘，Emby 继续读取本地 STRM。

当前这个功能配置在 115 的 STRM 同步目录里，不是给所有网盘通用的上传开关。开始前先完成 [账号管理](账号管理.md) 和 [生成 STRM](生成-STRM.md)。

## 先分清三个位置

| 位置 | 放什么 | 示例 |
| --- | --- | --- |
| 本地监控目录 | 准备上传的视频和元数据 | `/downloads/电影` |
| 115 目标目录 | 上传后的网盘文件 | `/电影/新片` |
| STRM 存放目录 | 上传成功后生成的 STRM 和复制的元数据 | 同步目录计算出的 `/media/电影` |

假设当前 STRM 同步目录的网盘来源是 `/电影`，监控规则把本地文件上传到 `/电影/新片`，生成结果就会落到该同步目录对应的本地路径中。监控目录下的相对层级会保留，例如本地的 `示例片/示例片.mkv` 会进入网盘目标下的同名子目录。

Docker 中的本地监控目录和 STRM 目录都是容器内路径，必须先做好挂载。**监控目录不要选 STRM 存放目录**，否则可能把生成结果再次当成上传来源。下载中的临时文件也应使用下载工具正常的临时文件名，完成后再移入监控目录或改为正式名称。

## 添加监控规则

1. 进入「STRM 同步 → STRM 同步目录」，编辑准备接收文件的 115 同步目录；也可以在新增目录时一起配置。
2. 确认已经选择 115 账号和来源路径，找到「目录监控上传」，开启总开关。
3. 填写开启总开关后自动出现的第一条监控规则，保持这条规则的开关开启。需要多条规则时再点击「添加监控目录」。
4. 选择本地「监控目录」和网盘「目标目录」。网盘目标必须在当前同步目录的来源范围内，例如来源为 `/电影` 时可选 `/电影/新片`，不能选 `/电视剧`。
5. 「监控模式」先选「自动（推荐）」。
6. 按需要选择「上传元数据」「遇到同名文件时」和「上传后删除源文件」，含义见下文。
7. 点击页面的「保存设置」，让同步目录和规则一起生效。

一个同步目录可以配置多条监控规则。不要让两条启用规则重复监控同一位置，也不要用递归父目录规则和子目录规则重复覆盖同一批文件。

新建规则默认也会检查已有文件。文件被发现后，会先等待大小和修改时间稳定，再排队上传，所以“目录里已经看到文件”不等于它已经开始或完成上传。

## 监控模式怎么选

| 模式 | 适合什么情况 |
| --- | --- |
| 自动（推荐） | 根据运行环境选择性能模式或兼容模式。Linux 上的网络共享、CloudDrive 等挂载目录可能直接使用兼容模式 |
| 性能模式 | 系统一发现新文件就主动通知 QMediaSync，适合通知可靠的本地磁盘；启动不了会报错 |
| 兼容模式 | 每隔一段时间检查一遍目录，适合通知不可靠的共享或挂载目录，发现文件可能稍有延迟 |

兼容模式的扫描周期由程序控制，页面没有扫描间隔或“稳定秒数”的设置。同步目录卡片会显示规则已启用的数量，实际启动或扫描异常需要查看应用日志；自动模式实际使用兼容模式时，不代表上传功能失效。

## 视频、元数据和过滤

视频扩展名沿用当前同步目录的 STRM 配置。开启「上传元数据」后，当前配置中的 NFO、图片、字幕等扩展名也会加入上传范围；关闭时只处理符合条件的视频。

隐藏路径、临时文件和回收站目录默认会被忽略，例如带 `.part`、`.tmp`、`.download`、`.aria2`、`.torrent` 临时后缀的项目。文件名或父目录命中 STRM 排除规则、视频小于最小大小阈值时，后续 STRM 生成也可能跳过。

上传成功后的处理分两种：

- 视频：生成对应的 `.strm`。
- 元数据：保留原文件名和扩展名，复制到对应的 STRM 本地目录，不会给 NFO 或图片再生成 `.strm`。

## 网盘已经有同名文件时

程序先检查同目录下的同名文件。**大小和 SHA1 都相同**时，会使用网盘已有文件继续生成 STRM，不必重复上传。这是复用已有文件，不是断点续传。

大小或内容不同时，按「遇到同名文件时」处理：

| 选项 | 实际后果 |
| --- | --- |
| 跳过 | 不上传当前本地文件，也不删除网盘同名文件 |
| 停止 | 当前文件停止处理并记录冲突错误，等待你确认应该保留哪一份 |
| 覆盖 | **先删除网盘同名旧文件，再上传本地新文件**。后续上传失败时，旧网盘文件已经被删除，不能把它理解成上传成功后才替换 |

不确定两端哪份内容正确时，先使用「跳过」或「停止」，核对冲突后再决定。

## 上传后删除源文件

默认关闭，适合首次配置和试运行。开启后删除的是**本地监控目录中的源文件**。

只有上传成功、对应文件的 STRM 后处理成功，且本地文件仍与上传时一致，程序才会清理源文件。元数据也要先完成本地复制，才能清理其来源文件。

以下情况不会按成功结果删除源文件：

- 上传失败、取消，或只是因同名冲突而跳过。
- STRM 生成或元数据复制失败、取消、被过滤跳过。
- 原路径的文件已被替换或修改，无法确认还是上传的那一份。

这个开关会在创建上传任务时记录是否需要清理；后来才开启，不会把之前所有保留的本地文件都自动补删。

删除源文件后，程序会向上清理因此变空的目录，但保留监控根目录。清理失败不会删除已经上传的网盘文件或回滚已经生成的 STRM，可以在上传任务详情查看「源文件清理」状态和原因。

## 查看进度和手动补扫

1. 在同步目录卡片点击「目录监控扫描」，可立即检查该同步目录下所有已启用的监控规则。
2. 提示中的“候选文件”数量表示发现了待检查的文件，不代表已上传成功；稳定性检查和去重之后才会进入上传队列。
3. 打开「上传下载 → 上传队列」，查看来源为「目录监控上传」的任务，展开详情检查上传结果、错误和源文件清理状态。
4. 确认实际 STRM 存放目录出现了结果，再检查 Emby 是否已扫描到新内容。

上传任务显示完成后，STRM 后处理仍可能继续。这个文件级处理不会新增完整 STRM 同步记录，也没有单独的“STRM 生成队列”页面；先检查实际文件、上传详情和应用日志。队列暂停、重试和清理说明见 [任务与通知](任务与通知.md)。

## 没有上传时先检查什么

- 总开关和对应规则开关是否都已开启并保存，卡片的「已启用 X 个 / 共 Y 个」是否符合预期；规则启用后仍未发现文件时，检查应用日志是否有启动或扫描错误。
- 监控目录是否是 QMediaSync 实际能读取的路径，Docker 挂载是否正确。
- 文件是否仍在写入、使用临时后缀，或被扩展名、隐藏目录等规则过滤。
- 115 账号是否仍有效，目标目录是否位于当前同步目录范围内。
- 上传队列是否暂停，或者文件已经按相同内容处理过。

先修正具体原因，再手动补扫。不要通过反复删除重建规则、清空任务来代替排查。
